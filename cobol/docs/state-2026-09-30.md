# State of the COBOL, 2026-09-30

A snapshot after one month: the first s32-cobc commit is dated 2026-08-29,
and 299 commits touch `cobol/` since. The focus is preservation: running
real COBOL faithfully on SLOW-32, and anywhere its emulators run.

First written the morning of 2026-09-30, and brought up to date that
evening. The day added:
- the computational usages: byte order, COMP-4/X/6 and floating point;
- compiled arithmetic, moves and compares, which cut the
  arithmetic-, move-, search- and string-heavy kernels' times by a third
  to two thirds, and majesty's jerm by four fifths (the file and sort
  kernels moved little);
- a gate that checks every program on both code paths;
- three more conformance sweeps.

## In one paragraph

s32-cobc compiles COBOL 85 to NIST's satisfaction: every CCVS-85
program compiles, runs to its summary and fails nothing. It covers most
of COBOL 2002 under `-std=2002`, including 31-digit arithmetic and now
floating point. It builds and runs the user's real ledger (majesty) and
the Open Systems accounting suite, and their outputs match their
references byte for byte. It embeds SQL on SQLite, gated by the NIST SQL
Test Suite, which was recovered from the Internet Archive for the
purpose. Its arithmetic, moves and compares now compile to registers
where the decimal stack's answer is provably the same. A gate checks
that on every run by compiling every program both ways. What is left
is mostly deliberate: features outside the preservation brief, SQLite's
own semantics, and a short list of real gaps.

## Conformance

**COBOL 85: NIST CCVS-85.**
- 348 of 348 programs compile and run to their summary.
- 8,068 of 8,175 tests pass and none fails.
- All 348 programs match GnuCOBOL's results exactly.
- Harness gate 5 holds the totals.
- The suite now also runs a second time with the register code paths
  off. Every program's tally, report and console output must match
  byte for byte: 658 files.

**COBOL 2002 (`-std=2002`):**
- National (UTF-16BE) and boolean/bit data;
- the exception-condition machinery (EC-*, RAISE, >>TURN, USE);
- user-defined functions, TYPEDEF and strong typing;
- pointers, ALLOCATE/FREE, LOCAL-STORAGE, RECURSIVE;
- SCREEN SECTION, READ PREVIOUS, table SORT, the 2002 intrinsics;
- 31-digit arithmetic (docs/wide.md);
- FLOAT-SHORT, FLOAT-LONG and FLOAT-EXTENDED (docs/usage.md).

By rule-by-rule sweeps against the text, 26 areas are written up in
docs/conformance/: ACCEPT, arithmetic, **arithmetic expressions**, CALL,
clauses, **relation conditions**, EVALUATE, EXIT, files, INITIALIZE,
I-O statements, MOVE, national/boolean, OCCURS, PERFORM, PICTURE,
RAISE, REDEFINES, RENAMES, SEARCH, SORT, STRING, >>TURN, USAGE
(**brought up to date**), USE and VALUE.

**What today's sweeps found:**
- **Exponentiation:** it associated right to left. The texts say left to
  right, so `2 ** 3 ** 2` is 64, and Micro Focus's reference agrees.
  `0 ** 0` gave 1 where the text says size error. Exponentiation's size
  errors now raise EC-SIZE-EXPONENTIATION.
- **Relation conditions:** four forms the texts forbid were accepted:
  a relation between two literals, and a noninteger, a binary item or
  an expression compared with text. A figurative constant stays exempt
  by ruling.
- **USAGE:** FLOAT-EXTENDED was missing. The 2014 floating forms were
  "unexpected"; they are now refused by name.

**Deliberately out:**
- VALIDATE (no implementor has done it);
- RESUME (optional since 2014);
- the COMMUNICATION SECTION;
- OO COBOL;
- floating-point literals (`1.5E3`) and external floating-point
  PICTUREs: 2002 and MF features no program here has asked for.

**The authority order:** NIST's cases first, then the standard's text,
then GnuCOBOL as the oracle where it agrees. For the usages Micro Focus
defines (COMP-X, COMP-5, COMP-1/COMP-2 as floats), its reference
decides. Every place we part from GnuCOBOL is recorded in
docs/oracles.md.

**Behavior points** (docs/behavior-points.md) are the preservation
mechanism. Where real code leaves the standard, it is taken and noted,
not refused:
- class E: 22 points, from RETURN-CODE to a separator comma with no
  space. BP-E3, the COMP-n usages, now takes in COMP-4, COMP-X and
  COMP-6;
- classes M, O and N: the 74-to-85 migration points.

Each is silent by default and reported under `-warn-extensions` or
`-warn-74`.

## The computational usages (docs/usage.md; ruled 2026-09-30)

- **COMP, BINARY, COMP-4:** big-endian, as IBM, Micro Focus and GnuCOBOL
  store them. A record written by any of them reads here.
  `-fbinary-byteorder=native` keeps SLOW-32's order. COMP-5 and the
  native usages stay in the machine's order.
- **COMP-X:** Micro Focus's unsigned big-endian binary, held to its
  capacity. A negative MOVE is stored in two's complement, and the 9s
  decide a size error. With X's it is n bytes, as COMP-5 with X's also
  is.
- **COMP-6:** unsigned packed decimal; a signed one is COMP-3.
- **COMP-1 and COMP-2:**
  - COMP-1 with a PICTURE stays RM/COBOL's binary (all 98 of the Open
    Systems suite's); without one it is an IEEE single.
  - COMP-2 is an IEEE double.
  - A statement with a float operand or receiver is computed in double.
  - DISPLAY uses MF's `.15000000E 01` form.
  - Floats work as ESQL host variables (REAL). NIST's dml035, the one
    program that met the old refusal, passes.

## Embedded SQL (docs/esql.md)

Phases 1 to 3 are done:
- static SQL;
- DB2's conventions: INCLUDE SQLCA, WHENEVER, host structures,
  CONNECT;
- dynamic SQL: EXECUTE IMMEDIATE, PREPARE/EXECUTE, dynamic cursors;
- GET DIAGNOSTICS and SQL descriptors;
- floating-point host variables.

The compiler is the precompiler. The runtime runs SQLite in the guest,
each schema a database file.

**NIST SQL Test Suite V6.0, embedded COBOL** (harness gate 5b):
- 421 of 429 programs compile and run;
- 386 tests pass and 445 fail.

**The ruling (the user, 2026-09-30):** SQLite as it is. The mappings
that use SQLite's own features are in: character columns compare
blank-padded through COLLATE RTRIM, and a normal end commits. The
failures are recorded, not emulated. Nearly all are SQL-92 that SQLite
lacks:
- updatable views, domains, ALL/ANY, datetime and intervals;
- INFORMATION_SCHEMA and privileges;
- DECIMAL arithmetic past 15 digits;
- scroll cursors (7 programs).

Full SQL-92 needs another backend. PostgreSQL, reached through an
emulator service, is on the roadmap as a second target, not now
(docs/esql.md).

The slow32:cobol container now builds SQLite and ships the ESQL runtime
beside libcob. A program with EXEC SQL compiles, links and runs in the
image.

What produced today's column, chosen by profiling only what the DBT
does not already run natively:

- **Arithmetic in registers.** Integer statements compute in a word:
  exact where the bounds prove it, and otherwise checked for overflow
  and falling back to the stack. Decimal statements of up to 18 digits
  compute as 64-bit scaled integers, with the scales fixed at compile
  time. Both are taken only where the stack's answer is provably the
  same. MOD, REM, INTEGER, INTEGER-PART and ABS are part of the same
  trees.
- **Numeric MOVE** compiles to the fetch and the store, without
  `cob_move`'s dispatch. Edited stores go straight to the natively run
  edit kernel.
- **Loops, compares and calls:**
  - loop steps are immediate adds;
  - short equality compares are in line;
  - user-function calls no longer allocate on every activation.
- **The runtime:**
  - INSPECT by a byte table;
  - UNSTRING's one-byte delimiter by a plain scan;
  - the indexed-file page cache by exact hash and CLOCK.

jerm's instructions fell from 26.4 G to 5.7 G. The remaining costs are
library algorithms (sort, string handling) and the native edit kernel.
The compiler's architecture is no longer the limit.

## What this work found elsewhere

The COBOL work acts as a test of the whole platform. This month it found:

- **stage08 cc:**
  - it folded INT64_MIN in a static initializer to 0 (selfhost
    ISSUES-70);
  - `NAN` and `INFINITY` from `<math.h>` failed at the link, because
    their builtins were not folded (selfhost ISSUES-71, found today by
    the float work on kagura);
  - both are fixed.
- **The x86-64 DBT** ran translated code with the stack 8 bytes off the
  ABI's alignment, so every native stub called host C misaligned. Fixed.
- **The AArch64 DBT's** hook decline path flushed a stale register
  cache. Fixed before it shipped.
- **The container build:** Dockerfile.cobol never copied SQLite into
  the build context. The builder session's fleet run found it; it is
  fixed.
