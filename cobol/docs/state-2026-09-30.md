# State of the COBOL, 2026-09-30

A snapshot after one month: the first s32-cobc commit is dated 2026-08-29,
and 283 commits touch `cobol/` since. The focus is preservation: running
real COBOL faithfully on SLOW-32, and anywhere its emulators run.

## In one paragraph

s32-cobc compiles COBOL 85 to NIST's satisfaction: every CCVS-85
program compiles, runs to its summary and fails nothing. It covers most
of COBOL 2002 under `-std=2002`, including 31-digit arithmetic. It
builds and runs the user's real ledger (majesty) and the Open Systems
accounting suite, byte-for-byte with their reference outputs. It now
embeds SQL on SQLite, gated by the NIST SQL Test Suite, which was
recovered from the Internet Archive for the purpose. This month the
benchmark kernels ran two to three times faster. What is left is mostly
deliberate: features outside
the preservation brief, SQLite's own semantics, and a short list of real
gaps.

## Conformance

**COBOL 85: NIST CCVS-85.**
- 348 of 348 programs compile and run to their summary.
- 8,068 of 8,175 tests pass and none fails.
- All 348 programs match GnuCOBOL's results exactly.
- Harness gate 5 holds the totals.

**COBOL 2002 (`-std=2002`):**
- National (UTF-16BE) and boolean/bit data;
- the exception-condition machinery (EC-*, RAISE, >>TURN, USE);
- user-defined functions, TYPEDEF and strong typing;
- pointers, ALLOCATE/FREE, LOCAL-STORAGE, RECURSIVE;
- SCREEN SECTION, READ PREVIOUS, table SORT, the 2002 intrinsics;
- 31-digit arithmetic (docs/wide.md).

By rule-by-rule sweeps against the text, 24 areas are written up in
docs/conformance/: ACCEPT, arithmetic, CALL, clauses, EVALUATE, EXIT,
files, INITIALIZE, I-O statements, MOVE, national/boolean, OCCURS,
PERFORM, PICTURE, RAISE, REDEFINES, RENAMES, SEARCH, SORT, STRING,
>>TURN, USAGE, USE and VALUE.

**Deliberately out:**
- VALIDATE (no implementor has done it);
- RESUME (optional since 2014);
- the COMMUNICATION SECTION;
- OO COBOL;
- floating-point usages (COMP-1 as a float, COMP-2, FLOAT-SHORT/LONG).
  This is the one gap real code has met: one NIST SQL program.

**The authority order:** NIST's cases first, then the standard's text,
then GnuCOBOL as the oracle where it agrees.

**Behavior points** (docs/behavior-points.md) are the preservation
mechanism. Where real code leaves the standard, it is taken and noted,
not refused:
- class E: 22 points, from RETURN-CODE to a separator comma with no
  space. Seven arrived with this month's corpora: E16 to E22;
- classes M, O and N: the 74-to-85 migration points.

Each is silent by default and reported under `-warn-extensions` or
`-warn-74`.

## Real programs

- **majesty**, the user's ledger:
  - its COBOL builds and runs (`validate_slow32.sh`: PASS);
  - the -std=2002 functions build is byte-identical: jerm's 400,001
    lines and the gltrans trio's 3,000 records.
- **The Open Systems accounting suite:**
  - 227 of 229 sources compile (the other two are a missing copybook
    and a fragment);
  - all seven modules' papers match;
  - the generated code is held byte-for-byte against a baseline
    compiler, which moves only on purpose.

## Embedded SQL (docs/esql.md)

Phases 1 to 3 are done:
- static SQL;
- DB2's conventions: INCLUDE SQLCA, WHENEVER, host structures,
  CONNECT;
- dynamic SQL: EXECUTE IMMEDIATE, PREPARE/EXECUTE, dynamic cursors;
- GET DIAGNOSTICS and SQL descriptors.

The compiler is the precompiler. The runtime runs SQLite in the guest,
each schema a database file.

**NIST SQL Test Suite V6.0, embedded COBOL** (harness gate 5b, 22
seconds):
- 420 of 429 programs compile and run;
- 385 tests pass and 445 fail.

**The ruling (the user, 2026-09-30):** SQLite as it is. The mappings
that use SQLite's own features are in: character columns compare
blank-padded through COLLATE RTRIM, and a normal end commits. The
failures are recorded, not emulated. Nearly all are SQL-92 that SQLite
lacks:
- updatable views, domains, ALL/ANY, datetime and intervals;
- INFORMATION_SCHEMA and privileges;
- DECIMAL arithmetic past 15 digits;
- scroll cursors (7 programs).

Full SQL-92 would mean a PostgreSQL backend reached through an emulator
service. It is designed, not built, and waits for a program that needs
it.

## Performance

M-series, slow32-dbt, the nine cobol/bench/vs kernels, in seconds:

| kernel | a month's work before hooks | now |
|---|---|---|
| karith | 3.31 | 1.44 |
| kmove | 1.76 | 1.06 |
| kedit | 2.06 | 0.91 |
| ksearch | 1.48 | 0.68 |
| kstring | 0.64 | 0.46 |
| ksort | 1.06 | 0.82 |
| kseq | 0.45 | 0.35 |
| kidx | 0.56 | 0.49 |
| kreport | 0.54 | 0.45 |

What produced these:

- DBT hooks: native kernels shared as source with libcob and tagged by
  checksum (docs/dbt-hooks.md);
- same-length alphanumeric compares compiled to memcmp;
- INSPECT, STRING and UNSTRING without a memcmp per character.

What remains is the decimal stack: most statements go through libcob.
Removing it is compiler work (inline binary arithmetic), to be done when
a workload asks for it; majesty's batch has not been re-timed since.

## What this work found elsewhere

The COBOL work acts as a test of the whole platform. This month it found:

- **stage08 cc** folded INT64_MIN in a static initializer to 0
  (selfhost ISSUES-70). Fixed; the kit is refreshed and mirrored to
  kagura.
- **The x86-64 DBT** ran translated code with the stack 8 bytes off the
  ABI's alignment, so every native stub called host C misaligned. Fixed.
- **The AArch64 DBT's** hook decline path flushed a stale register
  cache. Fixed before it shipped.
- **Phase 3 of the 31-digit work** had quietly doubled the cost of a
  FUNCTION MOD loop. Caught by profiling (`slow32 -p`, new) and fixed.

## Open, and waiting

- **Floating-point usages** (COMP-1/COMP-2, FLOAT-*): the one language
  gap real code has met.
- **Performance past the hooks:** inline decimal arithmetic in the
  compiler, when a real workload asks for it.
- **ESQL:**
  - scroll cursors, which need result buffering;
  - optionally updatable views (INSTEAD OF triggers) and
    INFORMATION_SCHEMA as views;
  - a PostgreSQL backend, if ever.
- **Operations, not yet done:**
  - the container images (slow32:emulator, slow32:cobol) need
    ~/builder's rebuild to carry this month's work: the hooks, the
    trampoline fix, esql.c, SQLITE_MAX_ATTACHED;
  - `~/bin/slow32-dbt`, which majesty uses by default, is a Sep 13 copy
    without hooks;
  - the public mirror (~/slow32-public) has not taken these commits.
    The ledger-scrubbing rules in CLAUDE.md apply to every message.
- **The issue log:** cobol/ISSUES.md runs to 117 items. Section A (the
  corpus) is closed; the rest is the engineering record.
