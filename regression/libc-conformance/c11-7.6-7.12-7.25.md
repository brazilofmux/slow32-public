# C11 7.6, 7.12, 7.25 Mathematics: the two C libraries

> Status 2026-11-01: 54 probes (`probes/7.12*.c`, `probes/7.6*.c`,
> `probes/7.25*.c`).  **rt** (clang + `runtime/`): 26 PASS, 12 DIFFER,
> 16 NOBUILD.  **sh** (stage08 cc + the selfhost library): 15 PASS,
> 12 DIFFER, 27 NOBUILD.  No TIMEOUT, no ORACLE-SPLIT, no `.expect` file.

This page covers `<fenv.h>` (7.6), `<math.h>` (7.12) and `<tgmath.h>`
(7.25).  Both libraries compute the same way: sh compiles
`runtime/math_soft.c` and `runtime/math_cordic.c` into its own library,
so every DIFFER below is one defect, seen twice.  The two libraries part
only where sh's headers lack something (`<fenv.h>`, `HUGE_VAL`,
`INFINITY`, `NAN`, `fpclassify`, `isnormal`, `signbit`, the `FP_*`
macros, `fma`), and that shows as NOBUILD.  In both libraries the
transcendental functions run in software on the reference emulator.  The
DBT and qemu swap the host's libm in by symbol, so a program run there
can print the right answer where the reference emulator does not.

Neither library defines `__STDC_IEC_559__`, so Annex F does not apply,
and nothing here requires its special values: signed-zero results,
infinities and NaNs as arguments.  The probes test only what 7.12 itself
requires.  A zero printed by `%g` is printed as `x + 0.0`, which removes
its sign.  Accuracy is printed to 12 significant digits or fewer, so a
last-ulp difference between implementations does not count.  C11 makes
the accuracy of `<math.h>` implementation-defined (5.2.4.2.2p6).  The
errors filed as accuracy errors below are therefore quality failures,
not conformance failures in the strict sense.  They are still listed
because neither library documents an accuracy, and every one of them is
wrong in the 10th digit or worse.

## Summary of gaps

**Wrong behaviour (DIFFER), both libraries, all in `runtime/math_soft.c`**

1. **`round` rounds 0.49999999999999994 to 1, and changes odd integers
   above 2^52** (`7.12.9.6-round-halfway`, `7.12.9.6-round-large`).
   7.12.9.6p2 rounds to the nearest integer.  Expected `round(0.49999999999999994)`
   = 0 and `round(4503599627370497.0)` = 4503599627370497; actual 1 and
   4503599627370498 (likewise -1 and -4503599627370498 for the
   negatives).  Cause: `round` is `floor(x + 0.5)`.  The addition rounds
   0.49999999999999994 + 0.5 up to 1.0, and an odd integer plus 0.5 is
   not representable above 2^52, so it rounds up to the even integer
   above.  Halfway cases (0.5, 2.5, -2.5) are right; `roundf` goes
   through double and is right.
2. **`modf` gives the wrong sign to a zero part** (`7.12.6.12-modf`).
   By 7.12.6.12p2 both parts carry the argument's sign.  `modf(-3.0, &i)`
   returns +0 (expected -0), and `modf(-0.5, &i)` stores +0 in `i`
   (expected -0).  Cause: the fraction is `x - trunc(x)`, which is +0 when
   x is integral, and `trunc` goes through `(long long)x`, which loses the
   sign of a zero.  The signs are tested with `copysign`, which works in
   both libraries.
3. **`pow` of a negative base to an integral exponent of 2^31 or more is
   NaN** (`7.12.7.4-pow-large-even`).  By 7.12.7.4p2 a domain error needs
   a non-integral y.  `pow(-1.0, 4294967296.0)` = 1 expected, NaN actual;
   `pow(-1.0, 4294967297.0)` = -1 expected; `pow(-1.0, 1e300)` = 1
   expected.  Cause: the integer test is `y == (double)(int)y`, which
   fails for any y outside int's range.  That test is also undefined
   behaviour (6.3.1.4p1) whenever y is out of int's range.  When it
   fails, the code goes to `x < 0 → NaN`.
4. **`exp`, `sinh` and `cosh` overflow early** (`7.12.6.1-exp-near-overflow`,
   `7.12.5-hyperbolic-near-overflow`).  `exp(709.5)` is 1.35e308 and
   `exp(709.78)` is 1.79e308, but both return inf.  `cosh(710.0)` and
   `sinh(710.0)` are 1.117e308, and both return inf.  These results are
   representable, so 7.12.1p5 gives no range error here.  Cause: `exp`
   returns inf for any `x > 709.0`; the true limit is about 709.78.
   `sinh` and `cosh` call `exp(|x|)` and inherit the limit, though they
   overflow only above about 710.47.  The other end, `x < -709.0 → 0`, is
   allowed: an underflowing result may be any value no larger than
   DBL_MIN (7.12.1p6).
5. **`pow` returns 0 for exact powers of two below DBL_MIN**
   (`7.12.7.4-pow-tiny-exact`).  `pow(2.0, -1030.0)` should be
   8.6916947597937554e-311 and `pow(2.0, -1074.0)` should be
   4.9406564584124654e-324; both return 0.  Both values are exactly
   representable, so this is not underflow (7.12.1p6 requires
   extraordinary roundoff).  Cause: a negative integral exponent is
   computed as `1.0 / pow(x, -y)`; 2^1030 overflows to inf, and 1/inf is
   0.  `pow(0.5, 1060.0)` goes the positive-exponent way and is right.
6. **The classification macros `isfinite`, `isinf`, `isnan` are
   functions** (`7.12.3-macros-defined`).  7.12.3.2-7.12.3.4 specify
   macros, and `#ifdef isnan` is false in rt (in rt, only `fpclassify`,
   `isnormal` and `signbit` are macros).  sh has none of the six as a
   macro: three are functions and three are missing.  The functions take
   `double`, so a `float` argument is still classified correctly.  For
   these three, the "argument's semantic type" rule of 7.12.3p1 cannot
   change the answer.
7. **Accuracy: argument reduction for trigonometric functions**
   (`7.12.4-trig-large-args`, `7.12.4-trig-near-zeros`).  `cos(1e15)`:
   expected -0.513193738, actual -0.590829974.  `sin(1e22)`: expected
   -0.85220085, actual +0.874028061.  `sin(1e6)` is wrong from about the
   11th digit.  `sin(3.141592653589793)`: expected 1.22465e-16, actual
   2.47903e-16.  `cos(1.5707963267948966)`: expected 6.12323e-17, actual
   2.47903e-16.  `sin(2*3.141592653589793)`: expected -2.44929e-16,
   actual 0.  `tan(1.5707963267948966)`: expected 1.63312e+16, actual
   1e+15.  Cause: `sin` reduces with `fmod(x, TWO_PI)`, using the double
   nearest 2π.  The `fmod` is exact, but the constant is off by about
   2.4e-16, so the error grows with x.  Near π, the Taylor sum cancels to
   noise.  `cos(x)` is `sin(x + π/2)`, and that addition rounds away up
   to half an ulp of x (0.06 at 1e15).  `tan` replaces any result above
   1e15 in magnitude with ±1e15.
8. **Accuracy: cancellation in `sinh`, `tanh`, `acos`**
   (`7.12.5-hyperbolic-small`, `7.12.4.2-acos-near-one`).
   `sinh(1e-5)`: expected 1.00000000002e-05, actual 1.00000000003e-05.
   `sinh(-1e-7)`: expected -1e-07, actual -9.99999999474e-08.
   `tanh(1e-8)`: expected 1e-08, actual 1.00000000613e-08.
   `acos(1 - 1e-12)`: expected 1.41419791987e-06, actual
   1.41419791988e-06.  Cause: `sinh` is `(e - 1/e)/2` for |x| above
   1e-10, and `tanh` is `(e^2x - 1)/(e^2x + 1)`; both subtract nearly
   equal values.  `acos` is `π/2 - asin(x)`, which cancels near 1.

**Missing pieces (NOBUILD)**

9. **No `math_errhandling`, `MATH_ERRNO`, `MATH_ERREXCEPT`**, in either
   library (`7.12-math-errhandling`).  7.12p9 requires them, and 7.12.1
   reports every domain, pole and range error through them.  Neither
   library sets `errno` in any math function: `sqrt(-1)`, `log(0)` and
   `exp(1000)` leave it 0.  rt's `<fenv.h>` has no exception flags, and
   7.12p9 allows MATH_ERREXCEPT only if `FE_DIVBYZERO`, `FE_INVALID` and
   `FE_OVERFLOW` are defined.  So the only conforming choice open to rt
   is MATH_ERRNO, which means setting `errno`.
10. **The C99 additions are missing in both libraries.**  Each line is a
    probe that does not build: the inverse hyperbolics
    (`7.12.5-inverse-hyperbolic`); `exp2`/`expm1`/`log1p`
    (`7.12.6-exp2-expm1-log1p`); `ilogb`/`logb`/`scalbn`/`scalbln`
    (`7.12.6-ilogb-logb-scalbn`); `FP_ILOGB0`/`FP_ILOGBNAN`
    (`7.12-ilogb-macros`); `hypot` (`7.12.7.3-hypot`); `erf`/`erfc`/
    `lgamma`/`tgamma` (`7.12.8-erf-gamma`); `nearbyint`/`rint`/`lrint`/
    `llrint` (`7.12.9-rint-nearbyint-lrint`); `lround`/`llround`
    (`7.12.9-lround-llround`); `remainder`/`remquo`
    (`7.12.10-remainder-remquo`); `nan`/`nextafter`/`nexttoward`
    (`7.12.11-nan-nextafter`); the six comparison macros
    (`7.12.14-comparison-macros`); `float_t`/`double_t`
    (`7.12-float-t-double-t`); `HUGE_VALL` (`7.12-huge-val`); and every
    `long double` (`l`-suffixed) function (`7.12-long-double-functions`).
11. **`<tgmath.h>` is missing in both** (`7.25-tgmath`).
12. **sh only:** no `<fenv.h>` at all (the four 7.6 probes).  Also
    missing from sh's `<math.h>` are `HUGE_VAL`/`HUGE_VALF`, `INFINITY`,
    `NAN`, the five `FP_*` classification macros, `fpclassify`,
    `isnormal`, `signbit`, and `fma`/`fmaf`.  That is why seven `<math.h>`
    probes that pass in rt do not build in sh.  The functions sh does
    have behave as rt's do: they are the same code.

**`<fenv.h>` in rt conforms.**  rt has one rounding direction and no
exception flags, and it says so.  It defines `FE_TONEAREST` and
`FE_ALL_EXCEPT` (= 0), and leaves the other `FE_*` macros undefined, as
7.6p6 and 7.6p8 allow.  `fesetround` refuses any other direction
(7.6.3.2p3).  The flag and environment functions succeed on the empty
set.  `FE_DFL_ENV` is a null `const fenv_t *`, which `fesetenv` accepts.

**Rulings.**  The two hosts never disagreed, so no `.expect` file was
needed.  Two probes were changed so that they test only what the
standard requires:

- `ceil`, `floor`, `trunc`, `round`: the sign of a zero result is
  Annex F's (F.10.6), not 7.12's.  The probes print `r + 0.0`.  (In rt,
  `trunc(-0.5)` and `floor(-0.0)` give +0 where both hosts give -0.)
- `pow(0, negative)` is a pole error (7.12.7.4p2), and 7.12.1p3 lets a
  pole error return any implementation-defined value.  rt and sh return
  0, which is permitted, so no probe tests it.  Both hosts return +inf.
  Returning 0 is a poor choice: the error is not reported by any other
  means (item 9), so 0 is the only result the caller sees.

**Outside the requirement (Annex F, noted from manual runs, no probe).**
`log(+inf)` never returns: `while (t > 2.0) t *= 0.5` does not terminate
for an infinity.  It ran 200M instructions on the reference emulator and
did not finish.  An infinite argument may be a domain error (7.12.1
footnote 231), but a library call that never returns is not one of the
permitted outcomes.  Also different from Annex F: `modf(inf)` returns a
NaN fraction (Annex F: 0); `atan2(-0.0, -1.0)` = +π (Annex F: -π);
`pow(-0.0, -3.0)` = 0 (Annex F: -inf); and `sin(-0.0)`, `floor(-0.0)`,
`round(-0.0)` and `trunc(-0.2)` return +0.
