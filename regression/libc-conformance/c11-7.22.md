# C11 7.22 General utilities `<stdlib.h>`: both C libraries

> Status 2026-11-01: 55 probes (`probes/7.22*.c`), run with `probe.py`
> against both libraries.  **rt** (clang + `runtime/`): 49 PASS, 3
> DIFFER, 3 NOBUILD.  **sh** (stage08 cc + the selfhost library): 43
> PASS, 3 DIFFER, 9 NOBUILD.  No ORACLE-SPLIT is left and no `.expect`
> ruling was needed (see "Oracle splits" below for the three probes
> rewritten instead).

Most of `<stdlib.h>` is in good shape in both libraries.  Integer
conversion (`strto[u]l[l]`, every edge the clause names), decimal and
hexadecimal `strtod` rounding (hard cases and 2,000-digit inputs alike),
`rand`/`srand`, the allocator, `atexit`/`exit`/`_Exit`/`abort`,
`qsort`/`bsearch`, and `div`/`ldiv` all pass.  The wrong behaviour is
concentrated in floating conversion's error reporting and in `strtof`,
plus one `calloc` overflow check in the selfhost library.  The missing
pieces are `quick_exit`/`at_quick_exit` and the whole of 7.22.7-7.22.8
(multibyte/wide) in both, and in sh `strtof`, `strtold`, `lldiv`,
`aligned_alloc` and `MB_CUR_MAX`.

## Summary of gaps

### Wrong behaviour (DIFFER)

1. **rt `strtof` rounds twice and never reports overflow** (7.22.1.3p5,
   p10).  `runtime/stdlib_utils.c` defines `strtof` as
   `(float)dtoa_strtod(...)`.
   - Double rounding: `strtof("1.00000005960464477539062501")` should be
     `0x3f800001` (the input is just above halfway between 1.0f and the
     next float); rt gives `0x3f800000`.  `strtod` rounds the value to
     exactly the halfway double, then the cast rounds that half to even.
     The same happens in hex: `strtof("0x1.0000010000000001p0")` should be
     `0x3f800001`, rt gives `0x3f800000` (`7.22.1.3-strtof`).
   - Overflow: `strtof("3.5e38")` returns `HUGE_VALF` correctly but leaves
     `errno` at 0; it must be `ERANGE`.  Every overflow case in
     `7.22.1.3-strtof-overflow` (`-1e39`, `1e300`, `0x1p128`,
     `3.40282357e38`) does the same: `strtod` sees no overflow, and the
     conversion to float that overflows sets nothing.
2. **rt `strtod`: hexadecimal input that rounds up past the largest double
   gives infinity without `ERANGE`** (7.22.1.3p10).
   `strtod("0x1.fffffffffffff8p1023")` returns `HUGE_VAL` (right) with
   `errno` 0 (should be `ERANGE`).  Decimal input in the same position
   (`"1.7976931348623159e308"`) and plain hex overflow (`"0x1p1024"`) are
   fine (`7.22.1.3-strtod-overflow`).  Likely cause: in `gethex()` in
   `runtime/dtoa.c`, the carry out of rounding is checked with
   `if (++e > Emax) goto ovfl;`, but `e` there is the exponent of the
   lowest bit, which the earlier range test compares with `emax`; the
   carried value lands in the exponent field as infinity without passing
   through `ovfl`.  sh shares this file, but see item 3.
3. **sh `strtod` never sets `ERANGE`** (7.22.1.3p10).  Every overflow in
   `7.22.1.3-strtod-overflow` returns the right `±HUGE_VAL` with `errno`
   left at 0; `strtod("1e309")` is the smallest case.  Cause:
   `selfhost/stage08/build-s12cc.sh` compiles the shared `runtime/dtoa.c`
   with `-DNO_ERRNO` (`DTOA_FLAGS`).
4. **sh `strtod` does not accept `NAN(n-char-sequence)`** (7.22.1.3p3).
   `strtod("nan(123)", &e)` returns a NaN but consumes only 3 characters;
   it should consume all 8.  Same for `"NaN(abc_9)x"` (10) and `"nan()"`
   (5); `"nan("` and `"nan(1"`, which have no closing parenthesis,
   correctly stop after 3 (`7.22.1.3-strtod-inf-nan`).  Cause: the same
   `DTOA_FLAGS` include `-DNo_Hex_NaN`, which compiles out dtoa's
   parenthesised-NaN parser.  rt, built without it, passes.
5. **sh `calloc(SIZE_MAX, SIZE_MAX)` returns a pointer** (7.22.3.2p2 with
   7.22.3p1: no object of that size can exist, so the call must fail).  The
   product wraps to 1 and a 1-byte block comes back.  Cause:
   `selfhost/stage08/libc/malloc.c` declares
   `char *calloc(int nmemb, int size)`, so the overflow test
   `total / nmemb != size` is done in signed `int`: (-1)·(-1) = 1, and
   1 / -1 == -1 == size, so it passes.  (The multiplication itself is
   signed overflow inside the library.)  Other wrapping products tested,
   `(SIZE_MAX/16+1)·32` and `(SIZE_MAX/2+2)·2`, are caught.

### Missing

6. **`quick_exit` and `at_quick_exit`** (7.22.4.3, 7.22.4.7): in neither
   library (`7.22.4.7-quick-exit`, NOBUILD both).
7. **Multibyte/wide characters and strings, 7.22.7 and 7.22.8**: `mblen`,
   `mbtowc`, `wctomb`, `mbstowcs`, `wcstombs` are in neither library
   (`7.22.7-mbtowc-wctomb`, `7.22.8-mbstowcs-wcstombs`).  In the "C"
   locale these are one-byte identity mappings, so the gap is small to
   close.  rt has `MB_CUR_MAX` (and it is 1, within `MB_LEN_MAX`); sh does
   not (`7.22.7-mb-cur-max`).
8. **sh lacks `strtof`, `strtold`** (7.22.1.3; `7.22.1.3-strtof`,
   `-strtof-overflow`, `-strtold`), **`lldiv` and `lldiv_t`** (7.22.6.2;
   `7.22.6.2-lldiv`), and **`aligned_alloc`** (7.22.3.1;
   `7.22.3.1-aligned-alloc`).  All are present and pass in rt (strtof
   aside, item 1).

Incidentally, several sh probes first failed to build for reasons outside
7.22, and were rewritten to avoid them (they belong to other clauses'
pages): no `<float.h>`, no `<wchar.h>`, no `HUGE_VAL` or `signbit` in
`<math.h>`, and no `SIZE_MAX` in `<stdint.h>`.  The probes now test
infinity, NaN and limits through the bit pattern.

### Oracle splits

No `.expect` file was written.  Three probes split the hosts on their
first run, all on behaviour the standard leaves open, and were rewritten
to test only what is guaranteed:

- `7.22.1.4-strtol-no-conversion`: macOS sets `errno` (to `EINVAL`, a
  POSIX "may fail") when there is no subject sequence; glibc leaves it.
  7.22.1.4p8 specifies only the return value and `*endptr` for this case,
  so the probe no longer prints `errno` there.
- `7.22.1.3-strtof` (first version): glibc set `ERANGE` for
  `"1.17549435e-38"`, a value just below `FLT_MIN` that rounds up to it;
  macOS did not.  Whether `errno` gets `ERANGE` on underflow is
  implementation-defined (7.22.1.3p10), so underflow cases print only
  the value, and overflow went into its own probe,
  `7.22.1.3-strtof-overflow`, where `ERANGE` is required.
  `7.22.1.3-strtod-underflow` likewise checks only the magnitude bound.
- `7.22.3.4-malloc-huge` and `7.22.3.2-calloc-overflow` (first versions):
  macOS printed "not null" for `malloc(SIZE_MAX)`.  Not a library
  answer: clang deletes an allocation whose result is only compared with
  null and folds the comparison to "not null".  rt, also clang, did the
  same.  The probes now call through a `volatile` function pointer, and
  both hosts agree.

Rulings on what to print: `rand`'s values, `RAND_MAX`, `malloc(0)`'s
choice, `EXIT_FAILURE`'s value and `system(NULL)`'s answer are
implementation-defined, so the probes print guaranteed facts about them
(in range, null-or-unique, differs from `EXIT_SUCCESS`, returns).
`7.22.4.1-abort-sigabrt` catches `SIGABRT` and leaves with `_Exit(7)`,
because the status of an uncaught abort is the host's.  Correct rounding
of decimal input (`-rounding`, `-long-digits`) is recommended practice in
7.22.1.3p9 rather than a requirement beyond `DECIMAL_DIG` digits; both
libraries meet it anyway.
