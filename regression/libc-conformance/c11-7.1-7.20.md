# C11 7.1-7.20 Small headers: both C libraries

> Status 2026-11-01: the survey as taken.  87 probes (`probes/7.1.*`,
> `7.2-*`, `7.2.1.1-*`, `7.4.*`, `7.5-*`, `7.7-*`, `7.8.*`, `7.9-*`,
> `7.10-*`, `7.13.*`, `7.15-*`, `7.16*`, `7.18-*`, `7.19-*`, `7.20.*`).
> **rt** (clang + `runtime/`): 70 PASS, 6 DIFFER, 11 NOBUILD.
> **sh** (stage08 cc + the selfhost library): 53 PASS, 9 DIFFER, 25 NOBUILD.
> No ORACLE-SPLIT, no TIMEOUT; one `.expect` ruling.

This page covers C11 7.1 (the library introduction: 7.1.2 headers, 7.1.4
use of library functions), 7.2 `<assert.h>`, 7.4 `<ctype.h>`, 7.5
`<errno.h>`, 7.7 `<float.h>`, 7.8 `<inttypes.h>`, 7.9 `<iso646.h>`, 7.10
`<limits.h>`, 7.13 `<setjmp.h>`, 7.15 `<stdalign.h>`, 7.16 `<stdarg.h>`,
7.18 `<stdbool.h>`, 7.19 `<stddef.h>` and 7.20 `<stdint.h>`, measured with
`tools/probe.py` against the tree's `runtime/libc_mmio.s32a` and
`selfhost/stage08/lib`, both on the reference emulator.  The expected
output is what macOS's libc and glibc both print.

Several of these headers are mostly the compiler's business.  Where a
failure is in code the compiler generates rather than in the library
(`va_arg`, `offsetof`), the page says so; the probe still counts against
the leg, since a program sees the two as one implementation.

The probes print only what the standard guarantees.  Kept out of the
output: the values of `EDOM`/`ERANGE`/`EILSEQ` (7.5p2 asks only for
distinct positive constants), the format of the assertion message
(7.2.1.1p2 leaves it implementation-defined; the probe checks only that
the required pieces are in it, and on stderr), how `NULL` is spelled
(7.19p3), and every size and limit beyond the standard's minimum and its
relation to the type it describes.  `FLT_ROUNDS == 1` at startup is
guaranteed only to an Annex F implementation (F.8.3); both hosts are,
SLOW-32's arithmetic is IEC 60559, and rt passes it, so it is kept in a
probe of its own (`7.7-flt-rounds-default`).

## Summary of gaps

**Wrong behaviour (DIFFER)**

1. **Both: a structure passed through `...` cannot be fetched with
   `va_arg`** (7.16.1.1p2).  `show(1, t, 42)` with `t = {7, 8, 9}` and
   `t = va_arg(ap, struct trio); after = va_arg(ap, int);` should give
   `7,8,9 42`; rt gives `251658240,547356672,-2138046464 12` and sh a
   similar mixture (`7.16.1.1-va-arg-struct`).  Compiler, not library.
   In rt the two halves of the ABI disagree: the caller passes the
   structure `byval`, which the backend puts on the stack (a pointer at
   `sp+0`) while the `42` after it still goes in `r4`; the callee's
   `va_arg` is lowered as an indirect fetch and reads `r4`'s save slot
   as the structure's address.  In sh, `va_arg` (stage08
   `hir_lower.h`, the SLOW-32 branch near line 3995) knows only 4- and
   8-byte scalars.
2. **sh: `va_start` finds the wrong first variable argument after a
   `long long` or `double` last parameter, or after more than eight named
   parameters** (7.16.1.4p3).  `f(long long x, ...)` called as
   `f(1LL, 4, 5)` reads `0` and then `4` instead of `4` and `5`; a `double`
   last parameter reads half of the double; with nine or ten named `int`
   parameters the first `va_arg` gives `0`.  One, or eight, named `int`s
   work.  Probe output `771 1.5 66 154`, expected `7 3.75 66 1145`
   (`7.16.1.4-va-start-param-types`).  Compiler: `va_start` is lowered
   to `__getfp()` (`hir_lower.h` near line 3987) whatever the named
   parameters are, so it is right only when each is one word and all
   came in registers.
3. **sh: `PRIdPTR`, `PRIuPTR` and `PRIxPTR` are `"lld"`, `"llu"` and
   `"llx"`, but `intptr_t` is 32 bits** (7.8.1p1).
   `printf("%" PRIdPTR " %d\n", (intptr_t)-5, 11)` prints
   `51539607547 4` for `-5 11`, and everything after it is shifted
   (`7.8.1-pri-ptr-dux`).  `selfhost/stage08/include/inttypes.h` says
   "same as 64-bit on this target", which holds for cc-x64/cc-a64, not
   SLOW-32; the right strings here are `"d"`, `"u"`, `"x"` (or keyed on
   `__SIZEOF_POINTER__`, as `stddef.h` already does).
4. **rt: `wchar_t` in `<stddef.h>` is not the type of `L'a'`**
   (7.19p2, 6.4.4.4p11, 6.4.5p6).  `runtime/include/stddef.h` has
   `typedef int wchar_t`, and `<stdint.h>` matches it (`WCHAR_MIN` is
   `INT32_MIN`), but clang's slow32 target makes wide constants
   `unsigned int` (`__WCHAR_TYPE__`).  `_Generic(L'a', wchar_t: 1,
   default: 0)` is `0`, as are the `L"ab"[0]` and `&L"ab"[0]` forms
   (`7.19-wchar-t`, expected `1 1 1`); `L'\0' - 1 > 0` while `WCHAR_MIN`
   is negative (`7.20.3-wchar-limits-vs-compiler`, `0 0` for `1 1`).  sh
   already uses `unsigned int`, matching its compiler.
5. **Both: re-including `<assert.h>` does not redefine `assert`**
   (7.2p1, 7.1.2p4).  After `#define NDEBUG` and a second
   `#include <assert.h>`, `assert(bump())` still evaluates `bump()`; after
   `#undef NDEBUG` and a third include it is still on.  Expected
   `off 0` / `on 1`, both print `off 1` / `on 2`
   (`7.2-ndebug-reinclude`).  Both headers put the `assert` definition
   inside the `_ASSERT_H` include guard; the standard wants it outside,
   with an `#undef assert` first.
6. **rt: a failing `assert` writes its message to stdout** (7.2.1.1p2:
   standard error).  `__s32_assert_fail` in `runtime/stdlib_extra.c`
   uses `printf`.  `7.2.1.1-assert-message` (stderr redirected to a
   file, read back in a `SIGABRT` handler) finds nothing on stderr; the
   message shows in stdout, which also turns `7.2.1.1-assert-false-aborts`
   into a DIFFER.  Otherwise rt's `abort` path is right: the handler runs
   and its `_Exit(3)` status comes back.
7. **Both: the assertion message does not name the enclosing function**
   (7.2.1.1p2 lists the argument text, `__FILE__`, `__LINE__` and
   `__func__`).  Neither macro passes `__func__`
   (`7.2.1.1-assert-message`, `function: 0`).  sh's message is otherwise
   complete and on stderr.
8. **sh: `LONG_MIN`, `LONG_MAX` and `ULONG_MAX` have type `int` and
   `unsigned int`** (5.2.4.2.1p1, via 7.10p2: each limit has its type
   after promotion, so `long` and `unsigned long`).  They are defined as
   `INT_MIN`, `INT_MAX`, `UINT_MAX` in `selfhost/stage08/include/limits.h`;
   `_Generic` tells (`7.10-limits-types`, `int int unsigned` for
   `long long unsigned long`).  Writing `2147483647L` etc. fixes it.
9. **sh: `int8_t` is plain `char`** (7.20.1.1p1 makes it a signed
   integer type, and 6.2.5p4 does not count `char` among them).
   `_Generic((int8_t)0, signed char: ..., char: ...)` picks `char`
   (`7.20.1.1-int8-signed-char`).  Its values are right (char is signed);
   the type is not, so `int8_t *` and `signed char *` are incompatible.
10. **sh: `va_start`, `va_arg`, `va_end` and `va_copy` are not macros**
    (7.16.1p1); `#ifdef` sees none of them (`7.16.1-macros`).  They work
    as parser intrinsics -- `va_copy` included, despite the inventory
    listing it missing (`7.16.1.2-va-copy` passes).
11. **sh: no `MB_LEN_MAX`** (5.2.4.2.1p1).  Counted as DIFFER because the
    probe's `#if MB_LEN_MAX >= 1` quietly evaluates to 0 rather than
    failing to build (`7.10-mb-len-max`).

**Missing pieces (NOBUILD)**

- Both: `static_assert` (7.2p3); `imaxabs`, `imaxdiv`, `imaxdiv_t`
  (7.8.2.1-2), `strtoimax`, `strtoumax` (7.8.2.3); the `PRI`/`SCN` macros
  for the least, fast and max types (7.8.1); `PRIiPTR`, `PRIoPTR`,
  `PRIXPTR`; `<tgmath.h>`, `<uchar.h>`, `<wctype.h>` (and for sh also
  `<float.h>`, `<iso646.h>`, `<locale.h>`, `<fenv.h>`, `<wchar.h>`), so
  `7.1.2-every-header` builds for neither.
- rt: the C11 `<float.h>` additions (`FLT_EVAL_METHOD`, `*_HAS_SUBNORM`,
  `*_DECIMAL_DIG`, `DECIMAL_DIG`, `*_TRUE_MIN`; 5.2.4.2.2); every
  `PRIi*`/`PRIo*` macro and `PRIX8`/`PRIX16`; every `PTR` and `MAX`
  `PRI` macro; all `SCN` macros except `SCNd32`, `SCNu32`, `SCNx32`.
- sh: all of `<float.h>` and `<iso646.h>` (so every 7.7 probe and
  `7.9-iso646` are NOBUILD); every `SCN` macro (its `sscanf` exists);
  the least and fast types and their limits (7.20.1.2-3), `INTPTR_*`,
  `UINTPTR_MAX`, `PTRDIFF_*`, `SIZE_MAX`, `SIG_ATOMIC_*`, `WCHAR_*`,
  `WINT_*` (7.20.2.4, 7.20.3), and the `INTN_C`/`INTMAX_C` macros
  (7.20.4).
- sh, compiler: `offsetof` takes only a plain member name.
  `offsetof(struct out, i.b)` and `offsetof(struct out, arr[3])` fail
  with "expected token 51" (7.19p3 allows any member designator that
  `&(t.designator)` accepts; `7.19-offsetof-designators`).  A plain
  member works, including as a constant expression in an array size,
  enumerator and case label (`7.19-offsetof`).

**Rulings**

- `7.1.2-every-header.expect`: macOS has no `<uchar.h>`, so the mac leg
  does not build while glibc prints `ok`.  7.1.2p2 lists `<uchar.h>` among
  the standard headers, and footnote 183 makes only `<complex.h>`,
  `<stdatomic.h>` and `<threads.h>` optional: glibc is right.  The
  ruling changes nothing for the SLOW-32 legs (both NOBUILD).
- No `.expect` for `7.2.1.1-assert-message`, but its design settles a
  split: macOS's message gives only the last component of the source
  file's name, glibc the whole `__FILE__`.  The probe looks for the last
  component, which both contain.

**What is right**

`<ctype.h>` is exact in both libraries: each of the twelve classifiers
and the two case mappings over all 256 `unsigned char` values and `EOF`,
in the "C" locale (bytes 0x80-0xFF in no class), called directly,
parenthesized, through `&name`, after `#undef`, and declared by hand
without the header (7.1.4p1-p2).  `<setjmp.h>` passes everything asked of
it in both, including `longjmp(env, 0)` returning 1, volatile locals,
unchanged non-volatile locals under register pressure after a jump from
thirty frames down, nested `jmp_buf`s and every context 7.13.1.1p4
allows.  `<errno.h>`, `<stdbool.h>` and `<stdalign.h>` pass in both, and
rt's `<float.h>` values agree with its arithmetic (epsilon, mantissa
digits, `MIN`, `MAX`, the decimal exponents) for all three types.
