# C11 7.11, 7.14, 7.24 Strings, locale, signals: both C libraries

> Status 2026-11-01: the survey as taken.  41 probes (`probes/7.24.*.c`,
> `probes/7.11*.c`, `probes/7.14*.c`; 40 new, plus the earlier
> `7.24.4.2-strcmp-sign`).
> **rt** (clang + `runtime/`): 41 PASS.
> **sh** (stage08 cc + the selfhost library): 33 PASS, 1 DIFFER, 7 NOBUILD.
> No ORACLE-SPLIT, no TIMEOUT, no `.expect` rulings.

This page covers C11 7.24 (`<string.h>`), 7.11 (`<locale.h>`) and 7.14
(`<signal.h>`), measured with `tools/probe.py` against the tree's
`runtime/libc_mmio.s32a` and `selfhost/stage08/lib`, both on the reference
emulator. The expected output is what macOS's libc and glibc both print;
they agreed on every probe here.

The probes test only what the standard guarantees. Things it leaves to the
implementation are kept out of the output: the text of `strerror`
(7.24.6.2p2), the name `setlocale` returns (7.11.1.1p7 says only that it
can restore the locale, 7.11.1.1p8), whether a handler is reset to `SIG_DFL` before it
runs (7.14.1.1p3), which signals start ignored (7.14.1.1p6), the exact
value `strxfrm` returns and the array's contents when that value is `n` or
more (7.24.4.5p3), and the magnitude of comparison results (only the sign
is printed).

## Summary of gaps

**Wrong behaviour (DIFFER)**

1. **sh: `strncat` with `n` of 2^31 or more appends nothing.**
   `strcpy(b, "ab"); strncat(b, "cd", (size_t)-1);` leaves `b` as `"ab"`;
   the expected result is `"abcd"`. Any `n` from `0x80000000` up does the
   same; `0x7fffffff` works (`7.24.3.2-strncat-large-n`). 7.24.3.2p2 makes
   `n` only an upper bound: the copy stops at s2's null, so a huge `n` is a
   legitimate "no limit" and nothing else about the call is out of range.
   Cause: `selfhost/stage08/libc/string_more.c` defines
   `char *strncat(char *dst, char *src, int n)`, so the `size_t` argument
   arrives negative and `while (i < n && ...)` never runs. The header
   declares the right prototype; the definition was written for the old
   subset-C compiler. rt's `strncat` (`runtime/string.c`) is correct.

   The same file defines `memcmp`, `memchr` and `strncpy` with an `int n`
   as well. Those are not observable from a conforming program here: each
   of them reads or writes all `n` bytes of the object (7.24.4.1p2,
   7.24.5.1p2, 7.24.2.4p2-3), and SLOW-32's 256 MB address space holds no
   object of 2 GiB. `strncmp` (`string_extra.c`) takes `unsigned int n`,
   which is `size_t`'s width, and passes the same large-`n` probe
   (`7.24.4.4-strncmp-large-n`).

**Missing pieces (NOBUILD)**

2. **sh has no `<locale.h>` at all**, as the inventory found: no
   `setlocale`, `localeconv`, `struct lconv` or `LC_*` macros. All seven
   7.11 probes are NOBUILD for that one reason. `strcoll` and `strxfrm`
   exist and behave as the "C" locale requires (`string_std.c`: byte
   order, and the identity transformation), which is all a program without
   `setlocale` can observe.

**Side note, outside this page's clauses**

3. sh's `<stdint.h>` has no `SIZE_MAX` (7.20.3). The two large-`n` probes
   first failed to build on that; they now spell it `(size_t)-1` so they
   test `<string.h>`. That gap belongs to the 7.20 page.

**Rulings on oracle splits**: none were needed.

**What held up.** Both libraries copy, move, fill and compare correctly at
every length 0..70 and every source/destination misalignment the probes
try, `memmove` in both overlap directions at distances 1..9 and over 2,000
bytes; compare bytes as `unsigned char`; convert `c` to `unsigned char`
(`memchr`, `memset`) or `char` (`strchr`, `strrchr`) as specified; find the
terminator with `strchr`/`strrchr`; return s1 for an empty `strstr`
needle; and handle `strtok` with leading and consecutive delimiters and a
delimiter set that changes between calls. rt's `<locale.h>` gives every
"C" locale value 7.11p2 specifies, rejects an unknown locale name
without changing the locale, and its composite `LC_ALL` name restores a
mixed locale. Both `signal` implementations return the previous handler,
honour `SIG_IGN` (including for `SIGABRT` through `raise`), run the handler
with the signal number before `raise` returns zero, and return `SIG_ERR`
with a positive `errno` for a number that is no signal.
