# C11 Expressions and Constant Expressions (6.5, 6.6): stage08 cc

> Status 2026-10-29: this is the 2026-10-28 survey as taken.  No WRONG or
> REJECTS is left (the complex-type probes are OPTIONAL), and of the
> survey's ACCEPTS only 9 remain, all rulings; `verdicts.txt` holds each
> probe's current verdict (320 PASS, 215 DIAG, 9 ACCEPTS, 3 OPTIONAL
> overall).

Range: N1570 clause 6.5 (every subclause, 6.5.1 through 6.5.17 including
6.5.1.1, 6.5.2.1-6.5.2.5, 6.5.3.1-6.5.3.4, 6.5.16.1-6.5.16.2) and 6.6.
Surveyed 2026-10-28 with `probe.sh` against the tree's stage08 cc.s32x.
111 probes (`probes/6.5*.c`, `probes/6.6*.c`): **31 PASS, 15 DIAG,
12 WRONG, 17 REJECTS, 36 ACCEPTS**, 0 ORACLE, 0 HANG.  Several DIAGs are
incidental (stage08 refuses the program for an unrelated missing feature,
not because it checks the constraint); they are marked below.

The evaluation core is sound: usual conversions at run time, sequencing of
`&&`/`||`/`?:`/comma, division/remainder, shifts, comparisons, bitwise and
logical operators, compound assignment (single evaluation of the lvalue),
block-scope compound literals, postfix chains, struct copy, and
integer constant expressions in enums, case labels, array bounds and
bit-field widths all pass.  The gaps cluster in five places: `_Bool`
conversion, integer-plus-pointer, a few type computations, static
initializers beyond the simplest forms, and constraint checking (almost
none of 6.5's type constraints are enforced).

## Summary of gaps

WRONG (wrong code, most serious first):

1. **integer + pointer is not scaled** (6.5.6p8).  `3 + ia` with `int ia[]`
   adds 3 bytes, not 3 elements; `ia + 3` is right.  Consequently the
   commuted subscript `2[a]` reads garbage for any element size > 1
   (`1["abc"]` happens to work).  Probes `6.5.6-int-plus-ptr`,
   `6.5.2.1-subscript-commuted`.  Smallest: `int a[4]; int *q = 3 + a;`
   gives `(char*)q - (char*)a == 3`.
2. **Conversion to `_Bool` truncates instead of comparing with zero**
   (6.3.1.2, reached through 6.5.4, 6.5.16.1, 6.5.2.4, 6.5.3.1, 6.6).
   `_Bool b = 0.5` is 0, `= 256` is 0, `= &x` is the low byte of the
   address; `(_Bool)h` likewise; `b++` on a true `_Bool` gives 2, `c--` on
   a false one gives 255, `++b` gives 2; in constant expressions
   `(_Bool)2 + 1` is 3 and `enum { E = (_Bool)256 }` is 256.  Probes
   `6.5.4-cast-bool`, `6.5.16.1-assign-bool`, `6.5.2.4-postfix-bool`,
   `6.5.3.1-prefix-bool`, `6.6-const-bool`.
3. **Postfix `++`/`--` on `double` does not modify the object** (6.5.2.4p2).
   `double d = 1.5; d--;` leaves 1.5 (also `d++`); the old value is
   returned correctly and `float` works.  Probe `6.5.2.4-postfix-double`.
   Smallest: `double d = 1.5; d--; printf("%.1f", d);` prints 1.5.
4. **Static initializers with double arithmetic fold wrongly** (6.6p8).
   `static double c = 2 + 0.25;` stores 2.00 (folded as int);
   `static double b = 1.0 / 4 + 2.0;` stores 0.17.  Probe
   `6.6-arith-const-double`.  (A single operation like `1.0 / 4` is fine.)
5. **Static initializers fold `int op long long` in 32 bits** (6.6p8 with
   6.3.1.8).  `static long long a = 0x7FFFFFFF * 2LL;` stores -2; the same
   expression at run time is right.  Probe `6.6-arith-const-llong`.
6. **Result types of unary `+ - ~` and of shifts** (6.5.3.3p2-4, 6.5.7p3).
   `sizeof(+uc)` and `sizeof(-uc)` are 1 (no promotion in the type; the
   value is computed correctly); `sizeof(1 << ll)` is 8 (shift typed by the
   usual arithmetic conversions instead of the promoted left operand).
   Visible only through `sizeof` / `_Generic`.  Probes
   `6.5.3.3-unary-promote-type`, `6.5.7-shift-result-type`.

REJECTS (valid C refused), roughly by how common the form is:

1. **`&function`** (6.5.3.2p1,3): `int (*fp)(int) = &f;` fails with "not
   an lvalue (hir)", both in a block and as a static initializer.  Very
   common in real code.  Probes `6.5.3.2-addr-function`,
   `6.6-address-const-func`.
2. **Address constants other than `&a[i]`, a bare array, or a function
   name** (6.6p9): `arr + 4`, `&arr[5] - 2`, `"hello" + 1`, `&gs.a`,
   `&gs.b[2]`, `(char *)&gs + 4` are all refused in static initializers
   (parse error "expected token 56", or "expected constant integer").
   Probes `6.6-address-const-offset`, `6.6-address-const-member`,
   `6.6-address-const-cast`.
3. **Static double initializers of the form `double + int` / `double +
   double`** (`0.25 + 2`, `2.0 + 0.25`): parse error; `3 / 2.0f` reports
   "division by zero in constant expression".  64-bit multiply/divide in a
   static initializer: "64-bit constant multiply or divide is not
   supported".  Probes `6.6-arith-const-double-int`, `6.6-arith-const-float`,
   `6.6-arith-const-llong-mul`.
4. **`_Generic`** (6.5.1.1) is not implemented at all ("unexpected token in
   expression").  Probes `6.5.1.1-generic`, `6.5.1.1-generic-noeval`,
   `6.5.1.1-generic-qualptr`.
5. **`_Alignof`** (6.5.3.4p3) is not a keyword: `_Alignof(char)` fails to
   parse, and `_Alignof(x)` compiles as a call to an undefined function.
   stage08 also has no `<stdalign.h>` (clause 7 note).  Probes
   `6.5.3.4-alignof`, `6.5.3.4-alignof-stdalign`.
6. **`__func__`** (6.4.2.2, used as a 6.5.1 primary) is undeclared.  Probe
   `6.5.1-func-name`.
7. **Member access on a struct-valued `?:`**: `(t ? a : b).y` fails "not an
   lvalue (hir)"; initializing from `t ? a : b` works.  Probe
   `6.5.15-cond-struct-member`.
8. **File-scope compound literals** (6.5.2.5p5): `static int *gp = (int[]){4,5,6};`
   is a parse error (DIALECT.md does say block scope only).  Probe
   `6.5.2.5-compound-file-scope`.
9. **VLAs and `sizeof` of a VLA** (6.5.3.4p2): any non-constant array bound
   is "expected constant integer".  VLAs are optional-ish in C11
   (`__STDC_NO_VLA__`), but stage08 does not define that macro.  Probe
   `6.5.3.4-sizeof-vla`.

ACCEPTS (constraint violations compiled silently) -- 36 probes; stage08
checks essentially none of 6.5's operand-type constraints.  It does catch:
undeclared identifiers, `->` on a non-pointer, unknown members, `&` of a
bit-field, assignment to a non-lvalue, non-constant case labels / static
initializers / enum values.  It does **not** catch:
- operand types of `[]`, unary `*`, `!`, `~`, `%`, `<<`, `&`, `^`, `|`,
  `&&`, `||`, `?:` first operand, `++` on a struct, casts to/from struct
  and pointer-to-double (6.5.2.1p1, 6.5.3.2p2, 6.5.3.3p1, 6.5.5p2, 6.5.7p2,
  6.5.10-6.5.14p2, 6.5.15p2, 6.5.3.1p1, 6.5.4p2,4);
- calling a non-function, wrong argument count or argument type against a
  prototype (6.5.2.2p1-2) -- the most consequential of these;
- pointer + pointer, subtraction or comparison of incompatible pointers,
  pointer vs integer ordering (6.5.6p2-3, 6.5.8p2, 6.5.9p2);
- assigning to a const object, an array, or a struct with a const member;
  `c++` on a const (6.5.16p2, 6.5.2.4p1);
- assignment type rules: int to pointer, dropping `const`, incompatible
  pointers, different struct types (6.5.16.1p1); `p += 1.5`, `p *= 2`
  (6.5.16.2p1-2);
- `&` of a `register` object (6.5.3.2p1); `sizeof` of an incomplete type or
  a bit-field (6.5.3.4p1);
- a floating constant directly in an integer constant expression
  (`enum { E = 2.5 }`, 6.6p6).

Incidental DIAGs (pass for the wrong reason): `6.5.1.1-generic-dup` and
`-nomatch` (no `_Generic` at all), `6.5.3.4-alignof-expr` (link error for
an undefined function `_Alignof`), `6.5.2.5-compound-vla` (no VLAs),
`6.5.15-cond-mismatch` ("not an lvalue", not a type check),
`6.6-comma-in-ice` (parse error rather than an ICE rule).

Aside: brace-initializing a struct that has a bit-field member
(`struct S { int b:3; } s = {1};`) is refused with "bit-field in struct
initializer unsupported" -- 6.7.9 territory, noticed while writing the
bit-field probes here.
