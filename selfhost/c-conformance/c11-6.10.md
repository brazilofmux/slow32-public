# C11 6.10 Preprocessing directives: stage08 cc

Range: C11 (N1570) clause 6.10 and every subclause 6.10.1 to 6.10.9,
plus a note row for 6.11.  Surveyed 2026-10-28 against the tree's
`selfhost/stage08/cc.s32x` (preprocessor in `selfhost/src/pp.h`).
97 probes (`probes/6.10*.c`, helpers in `probes/inc/6.10.2-*.h`,
`6.10.8-where.h`, `6.10.9-once.h`): **35 PASS, 5 DIAG, 16 WRONG,
12 REJECTS, 29 ACCEPTS**, no ORACLE, no HANG.  The everyday core
(object/function-like macros, `#if`/`#elif` chains, `defined`, `#include`
"..." and <...>, include guards, `#pragma once`, `##` of identifiers and
numbers, simple variadics, rescanning and the no-recursion rule) works.
What fails clusters in a few root causes, listed below; the large ACCEPTS
count is one fact seen 29 ways: stage08's preprocessor diagnoses almost
nothing (only a missing include file and `#error`).

## Summary of gaps

WRONG (wrong output from a valid program), most serious first:

1. **`__LINE__` counts lines of the spliced translation unit, not of the
   source file** (6.10.8.1).  Any `#include` before the use shifts it: a
   3-line program with `#include <stddef.h>` on line 2 returns `__LINE__`
   = 21 from line 3.  Every `assert()` message and stage08's own error
   line numbers (`s12cc:214:` in a 20-line file) inherit this.
   Probe `6.10.8.1-file-line`.
2. **`__FILE__` inside a header names the includer**, not the header
   (6.10.8.1; DIALECT.md lists this as a known thin spot).
   Probe `6.10.8.1-file-in-header`.
3. **An argument is not macro-expanded before substitution when the
   receiving macro passes it on to `#` or `##`** (6.10.3.1p1).  The
   classic two-level idiom fails: `XSTR(VAL)` gives `"VAL"`, not `"42"`;
   `XSTR(__LINE__)` gives `"__LINE__"`; `xglue(HIGH, LOW)` with `LOW`
   defined pastes the unexpanded `LOW`.  stage08 seems to substitute the
   raw argument and expand only on rescan, after the inner `#`/`##` has
   already consumed it.  Probes `6.10.3.2-xstr`, `6.10.3.3-hash-hash-token`,
   `6.10.3.3-placemarker` (its `XS(T(,,))` part), `6.10.3.5-example4-str-glue`.
4. **`#__VA_ARGS__` is always `""`** (6.10.3.1p2 + 6.10.3.2p2).
   Probes `6.10.3-variadic-stringize`, `6.10.3.5-example7-variadic`.
5. **`m(m)` re-expands the inner `m`** (6.10.3.4p2): with
   `#define m(a) a(3)` and a function `m`, `m(m)` must call the function;
   stage08 emits `3(3)`, a call to address 3, and the program faults
   (exit 139).  The front end also accepts calling an `int` without a
   diagnostic (a 6.5.2.2 matter, outside this page).  Probe
   `6.10.3.4-painted-arg`.
6. **`#if` arithmetic is signed only** (6.10.1p4): `-1 < 0u` is true,
   `(0u - 1) > 0` false, `0xFFFFFFFFFFFFFFFF >> 63` is not 1.  64-bit
   width is right.  Probe `6.10.1-if-unsigned`.
7. **`#line` is ignored** (6.10.4), so `__LINE__`/`__FILE__` after it are
   unchanged.  DIALECT.md documents the no-op.  Probes `6.10.4-line`,
   `6.10.4-line-macro`.
8. **Stringizing keeps comments**: `S(a/**/b)` gives `"a/**/b"`, and a
   `//` comment inside a multi-line argument is spelled into the string
   (translation phase 3 should have made both a space).  Probes
   `6.10.3.2-stringize-comment`, `6.10.3.5-example4-str-glue`.
9. **Stringizing escapes a `\` that is outside any literal**: `S(a\n)`
   must be `"a\n"` (a newline when printed); stage08 gives `"a\\n"`.
   Probe `6.10.3.2-stray-backslash`.
10. **`__STDC_VERSION__` and `__STDC_HOSTED__` are not defined** (6.10.8.1,
    both mandatory).  stage08 predefines only `__STDC__` (1), `__S12CC__`,
    `__STDC_NO_ATOMICS__` and arch macros.  Should it say 201112L?  Only
    together with the C11 opt-outs it needs: C11 made VLAs, complex and
    threads optional, so `__STDC_VERSION__ 201112L` plus
    `__STDC_NO_VLA__`, `__STDC_NO_COMPLEX__` and `__STDC_NO_THREADS__`
    would be an honest description.  Today stage08 defines none of those
    three yet supports none of the features (probes
    `6.10.8.3-feature-vla`, `-complex` REJECT on the `#ifndef`'d code),
    so portable code keyed on them takes the wrong path.  Leaving
    `__STDC_VERSION__` undefined makes code that tests `>= 199901L` think
    it is on C89.  `__STDC_HOSTED__` is a one-line call (1, since a libc
    with stdio ships).  Probes `6.10.8.1-stdc-version`,
    `6.10.8.1-stdc-hosted`.

REJECTS of valid C:

11. **Empty argument to a plain parameter**: `#define OR0(a) (a + 0)`,
    `OR0()` leaves the parameter name `a` in the output (works when the
    parameter is next to `#` or `##`).  Probes `6.10.3-empty-args`,
    `6.10.3.5-example3-rescan` (its `q()`).
12. **Computed `#include`** (6.10.2p4): `#include INCFILE` and
    `#include STR(path)` are silently skipped, not even diagnosed
    (`pp_include` returns quietly when the next char is not `"` or `<`).
    Probes `6.10.2-include-computed`, `6.10.2-include-computed-angle`.
13. **`_Pragma` is not implemented** (6.10.9) -- parsed as an identifier,
    "expected type".  Probes `6.10.9-pragma-operator`, `6.10.9-pragma-once`.
14. **`__DATE__`/`__TIME__` are not defined** (6.10.8.1).
    Probe `6.10.8.1-date-time`.
15. **`##` that forms a punctuator** (`+ ## =` to `+=`, `< ## <=`) fails
    to parse.  Probe `6.10.3.3-paste-punct`.
16. **`##` in an object-like macro** (`#define J ab ## cd`) is not pasted.
    Probe `6.10.3.3-object-paste`.
17. **A function-like macro name whose `(` is on the next line** is not
    invoked (6.10.3p10 makes new-line ordinary white space there).
    Probe `6.10.3-paren-next-line`.

ACCEPTS (constraint or syntax violations taken silently) -- 29 probes,
one cause: the preprocessor has no checking layer.  Not diagnosed:
unknown directive names; a `#` produced by macro expansion is treated as
a directive (`EMPTY # define Z 1` defines Z); malformed `#if` (empty,
dangling operator, `=`, floating constant, bare `defined`); `#elif`
after `#else`, stray `#endif`, unterminated `#if`; malformed `#include`
(empty, non-name); every macro-redefinition rule of 6.10.3p1-2 (the
later definition silently wins); missing white space after an
object-like name; duplicate parameter names; `__VA_ARGS__` in a
non-variadic macro; too many macro arguments (extras dropped); `#` not
before a parameter; `##` at either end of a list; all four bad `#line`
forms; `#define defined`; `#undef __LINE__`.  The three DIAG verdicts on
macro-argument-count probes (`too-few-args`, `unterminated-call`,
`variadic-missing`) come from the C parser tripping over the leftover
parameter name, not from the preprocessor.
