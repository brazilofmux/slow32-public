# C11 6.7 Declarations: stage08 cc

> Status 2026-10-29: this is the 2026-10-28 survey as taken.  No WRONG or
> REJECTS is left (the complex-type probes are OPTIONAL), and of the
> survey's ACCEPTS only 9 remain, all rulings; `verdicts.txt` holds each
> probe's current verdict (320 PASS, 215 DIAG, 9 ACCEPTS, 3 OPTIONAL
> overall).

This survey covers C11 clause 6.7 (Declarations), 6.7 through 6.7.10, against the
tree's stage08 cc (`selfhost/stage08/cc.s32x`) as of 2026-10-28. The method is
the one in `probe.sh`: clang `-std=c11 -pedantic-errors` decides validity, and
both builds run on the reference interpreter. There are 116 probes in
`probes/6.7*.c`, with these verdicts: **26 PASS, 27 DIAG, 24 REJECTS, 7 WRONG,
32 ACCEPTS**, 0 ORACLE, 0 HANG.

Several of the 27 DIAG verdicts are vacuous. The program was refused, but only
because the feature itself is missing (`_Alignas`, `_Thread_local`, VLAs,
`[static N]`), not because the constraint was checked. Those rows are marked
"vacuous" below.

## Summary of gaps

**WRONG: wrong code from valid C**

1. **`_Bool` objects do not convert their values** (6.3.1.2p1). `_Bool b = 2;`
   stores 2, `b = 256;` stores 0 (the value is truncated to a byte), and
   `_Bool d = 0.5;` stores 0. This happens on initialization and on assignment,
   for statics and for automatics. Probe: `6.7.2-bool-object`.
2. **`sizeof(int (*)[3])` evaluates to 12.** In a type name, a pointer to an
   array is read as an array of pointers. Probe: `6.7.7-type-names`. Declaring
   a pointer-to-array object is rejected outright; see REJECTS item 4.
3. **A struct or union tag redefined in an inner block does not shadow the outer
   tag** (6.7.2.3p4, 6.2.1p4). The case is
   `struct t {int a;}; ... { struct t { double x; char y; } v = {1.0,'z'}; }`.
   The inner `v` is laid out as the outer `struct t`, and the output is garbage
   bytes. (`struct t;` followed by a redefinition in the same block works.)
   Probe: `6.7.2.3-block-tag-shadow`.
4. **Block-scope enumerators leak out of their block** (6.2.1p4).
   `{ enum { X = 100 }; } X` evaluates to 100 after the block, when it should be
   the outer `X`. Probe: `6.7.2.2-enum-scope`.
5. **An unsigned bit-field narrower than `int` promotes to `unsigned`, not `int`**
   (6.3.1.1p2). With `unsigned u:4` holding 1, `x.u - 2 < 0` evaluates to 0.
   Probe: `6.7.2.1-bitfield-promote`.
6. **A brace-enclosed string initializer is wrong** (6.7.9p14).
   `char a[] = { "hi" };` gets size 1 and holds an empty string, and
   `char b[5] = { "abc" };` holds an empty string. Probe: `6.7.9-braced-string`.
7. **Bit-field layout differs from clang's SLOW-32 ABI** (6.7.2.1p11). The layout
   is implementation-defined, but it breaks interop with clang-built objects.
   `{unsigned x:3; _Bool f:1;}` is 8 bytes under stage08 and 4 under clang;
   `{char c; unsigned x:3;}` is 8 against 4; `{char; unsigned short h:4; char;}`
   is 6 against 4. stage08 starts a new unit where clang packs into the current
   one. Probe: `6.7.2.1-bitfield-layout`.

Found outside this range while writing probes: **`double`/`float` multiplied by
an integer constant that is a power of two (≥ 2) gives the wrong result.**
`double twice(double f) { return f * 2; }` compiles to `fdiv.d f, (double)1`,
so it returns `f`. `f * 3`, `f * 2.0` and `f * k` with `int k` are all correct.
The likely cause is a mul-to-shift/reciprocal rewrite applied to a floating
operand. This belongs to 6.5.5. The minimal reproducer is the one-line `twice` above.

**REJECTS: valid C refused, most common first**

1. **No VLAs at all** (6.7.6.2p4-5): local `int a[n]`, `sizeof` of a VLA,
   VLA typedefs, and `int a[n][n]` and `[*]` parameters. Every case fails with
   "expected constant integer".
2. **Declarators the parser cannot read in a declaration list.**
   - `int x, (*fp)(void), f(void);` is rejected (6.7p1).
   - `typedef int A, *AP;` and `typedef struct {…} Pt, *PtP;` are rejected
     (6.7.8). A typedef can take only a single declarator.
3. **A function-typed parameter is rejected** (6.7.6.3p8). `int apply(int f(int), int x)`
   fails, while the `int (*f)(int)` spelling works.
4. **Pointer-to-array declarators are rejected.** This covers `int (*pa)[3]` as a
   file-scope or local object (it works as a parameter or member) and
   `int (*f(void))[3]` (6.7.6.1). It also covers the type name
   `int (*[2])(void)` (6.7.7).
5. **A struct initializer that sets any named bit-field is rejected**: "bit-field
   in struct initializer unsupported". This includes `= {0}`, positional
   initializers, and `.bf = x` (6.7.9). Bit-fields work through assignment.
6. **An array typedef with an initializer is rejected.** `typedef int A[3]; A x = {1,2,3};`
   fails, with or without `const` (6.7.8, 6.7.3p9).
7. **A static initializer of the form address-plus-offset is rejected.**
   `static int *q = arr + 1;` and `"hello" + 1` fail, while `&arr[1]` works
   (6.7.9p4, 6.6p9).
8. **Type specifiers are accepted only in the usual order.** `int signed`,
   `int long long`, `short unsigned int` and `int unsigned long` are rejected
   (6.7.2p2).
9. **`_Alignas` and `_Alignof` are not recognized at all** (6.7.5, 6.5.3.4). There
   is no `<stdalign.h>`.
10. **`_Noreturn` is not recognized** (6.7.4p8), and there is no `<stdnoreturn.h>`.
11. **`_Thread_local` is not recognized** (6.7.1).
12. **The array-parameter forms `[static N]`, `[restrict static N]` and `[const]`
    are rejected** (6.7.6.3p7).
13. **`_Static_assert` inside a struct declaration is rejected** (6.7.2.1p1).
14. **An old-style (identifier-list) function definition is rejected** (6.9.1).
    This form is obsolescent.
15. **`double _Complex` is rejected.** Complex types are an optional feature.
16. **A non-extern incomplete array that is completed later is rejected**:
    `int ext[]; int ext[4] = {…};`. The `extern int ext[];` form works. Not
    probed separately.

**ACCEPTS: constraint violations taken silently, most consequential first**

1. **`_Static_assert` is checked only when its expression is a bare literal**
   (`parser.h`, both sites: "only supports ND_NUM"). Every other expression,
   `1 == 2` and `sizeof(char) == 2` included, is treated as true, and a
   non-constant expression is accepted too.
2. **`const` is not enforced anywhere** (6.5.16p2). The following are all
   accepted: assignment to a const local or global, `++` on a const object,
   a store through `const int *`, assignment of a struct that has a const
   member, and `int *p = &const_obj` (discarding a qualifier, 6.5.16.1).
3. **Redeclaration checks are missing.** Accepted without a word:
   - `int a; int a;` in one block (6.7p3);
   - `extern int x; extern long x;` (6.7p4);
   - `int f(int); int f(double);` (6.7.6.3p15);
   - `typedef int T; typedef long T;`;
   - a struct defined twice in one scope (6.7.2.3p1);
   - a tag used as both `struct` and `union` (6.7.2.3p2);
   - duplicate member names (6.7.2.1).
4. **A call with too many arguments to a prototyped function is accepted**
   (6.5.2.2p2).
5. **Function declarators are not validated.** A function returning an array or
   a function type is accepted (6.7.6.3p1), and so is `(void, int)`
   (6.7.6.3p10).
6. **Storage-class and specifier misuse is accepted**:
   - `static extern` (6.7.1p2);
   - `&` of a `register` object;
   - `inline` on an object or on `main` (6.7.4);
   - `restrict int` (6.7.3p2);
   - `_Atomic` applied to an array or function type (6.7.2.4p3, 6.7.3p3).
7. **Constant-range checks are missing.** These are accepted: `int a[0]`
   (6.7.6.2p1), `char s[2] = "abc"` (6.7.9p2), an enumerator outside `int`'s
   range (6.7.2.2p2), and a forward `enum` reference (6.7.2.3p3).

Clause 7 notes: stage08 `include/` has no `<stdalign.h>`, `<stdnoreturn.h>` or
`<float.h>`. Neither libc's `<assert.h>` (stage08 or runtime/) defines the
`static_assert` macro (7.2p3), which is why no probe for it was kept.
