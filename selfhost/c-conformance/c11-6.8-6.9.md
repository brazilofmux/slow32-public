# C11 6.8-6.9 Statements and external definitions: stage08 cc

This page covers C11 clauses 6.8 (statements and blocks) and 6.9 (external
definitions), measured with `probe.sh` on 2026-10-28 against the tree's
`selfhost/stage08/cc.s32x`. There are 92 probes (`probes/6.8*.c` and
`probes/6.9*.c`): 44 valid and 48 invalid. The verdicts are **26 PASS, 23
DIAG, 5 WRONG, 13 REJECTS, 25 ACCEPTS**, with no ORACLE and no HANG. Nine
of the 23 DIAGs are right only by accident: stage08 refuses those
programs for a reason unrelated to the constraint being probed (no VLAs,
no old-style definitions, a parse error, or a failure that only shows at
link time). The note column marks each one.

## Summary of gaps

**WRONG code, and "REJECTS" that are really wrong code**

1. **A `goto` into a compound statement, when the block holding the label
   is reachable only through that goto, deletes the whole function body.**
   The `.s` contains `main:` and nothing else, so the link fails with
   "unresolved symbol: main". The smallest case is
   `goto in; { in: x += 7; }` (`6.8.6.1-goto-into-block`). Jumping into a
   loop body fails the same way (`6.8.6.1-goto-into-loop`, the pattern of
   the standard's own 6.8.6.1 example). The harness says REJECTS, but the
   compiler accepted the program without complaint; the code is lost
   afterwards. An earlier combined probe that mixed this with other
   gotos HUNG at run time instead of failing to link.
2. **Undefined labels produce the same empty function.**
   `goto nowhere;`, or a goto naming a label in another function, compiles
   silently to an empty `main` (`6.8.6.1-goto-undefined-label`,
   `-goto-other-function`; ACCEPTS once a second function makes the link
   go through). Item 1 probably has the same cause: label resolution
   failing quietly and the function being thrown away.
3. **A `switch` on a `long long` compares only the low word.** In
   `switch (v) { case 1: ...; case 0x100000001LL: ... }`, a value of
   `0x100000001` takes `case 1`, and `0x200000001` does too instead of
   `default`. The same happens for `unsigned long long`
   (`6.8.4.2-switch-longlong`).
4. **A switch body that is not a compound statement is miscompiled.**
   `switch (x) default: r += 3; return r;` returns garbage, and
   `switch (x) case 9: r = 99;` returns 0 when nothing matches
   (`6.8.4.2-switch-unbraced-body`). Braced bodies are fine.
5. **Falling off the end of `main` does not return 0.** The exit status
   is whatever is left in the return register; it was 3, `printf`'s
   return value (`6.9.1-main-fall-off`; the rule is 5.1.2.2.3, cited from
   6.9.1p12).
6. **Converting to `_Bool` truncates instead of comparing with 0.**
   `_Bool b = 5;` holds 5, so `switch (b)` misses `case 1`, and
   `_Bool f(int x){return x;}` returns 0 for 256 (`6.8.4.2-switch-bool`,
   `6.8.6.4-return-bool`). The root cause is in 6.3.1.2 conversion, but it
   shows up as wrong code in these statements.

**REJECTS of common C**

7. **A `for` declaration may have only one declarator, of a simple
   type.** `for (int i = 0, j = n; ...)` is rejected. So are a `register`
   declaration, an array with a pointer into it, and a struct type defined
   in place (`6.8.5.3-for-decl-two`, `-register`, `-array-pointer`,
   `-struct`). `for (int i = 0; ...)` works. The two-declarator form is
   the most common C99 idiom on this list.
8. **Old-style (K&R) function definitions are not supported at all.**
   Even `int twice(x) int x; { ... }` fails with "expected type in params"
   (`6.9.1-kr-minimal`, `-kr-definition`). As a result, the four K&R
   constraint probes are DIAG only by accident.
9. **A parameter declared with a function type,
   `int apply(int f(int), int v)`, is rejected**
   (`6.9.1-param-function-type`). Writing `int (*f)(int)` works.
10. **A tentative definition of an incomplete array is rejected.**
    `int a[];` at file scope fails, whether a later `int a[4];` completes
    it (`6.9.2-tentative-array-completed`) or nothing does and it should
    become a one-element array (`6.9.2-tentative-array-one`). The error is
    "array size required without initializer".
11. **An `extern` object of an incomplete struct type is rejected.**
    `struct pt; extern struct pt pv;` fails before the struct is completed
    (`6.9.2-extern-incomplete-struct`), with "incomplete global type".
12. **No VLAs** (`6.8.2-vla-per-entry`): "expected constant integer". The
    feature belongs to 6.7.6.2, and it is optional in C11 (but then
    `__STDC_NO_VLA__` should be defined). The two VLA-jump constraint
    probes are DIAG by accident for the same reason.

**ACCEPTS (constraints not diagnosed)**

13. Switch constraints: duplicate case values (also after conversion to
    the controlling type), two `default`s, a non-integer case constant
    (`case 1.5`), and a non-integer controlling expression (`double`,
    pointer) are all accepted. A `case` or `default` outside any switch is
    accepted too. (`6.8.4.2-case-duplicate*`, `-default-twice`,
    `-case-float-constant`, `-switch-double`, `-switch-pointer`,
    `6.8.1-case/default-outside-switch`)
14. A non-scalar controlling expression is accepted: `if`, `while` or `for`
    on a struct (`6.8.4.1-if-struct`, `6.8.5-*-controlling-struct`).
15. Return constraints: `return 1;` in a `void` function, a bare `return;`
    in an `int` function, and returning a struct from an `int` function
    are all accepted (`6.8.6.4-return-*`).
16. Duplicate labels in one function are accepted (`6.8.1-duplicate-label`).
    So is a label directly before a declaration, which is a C23 extension
    (`6.8.1-label-before-declaration`).
17. External definitions: `auto` or `register` at file scope, `register`
    on a function definition, a function defined twice, a function
    returning an array or function type, and `int x; static int x;` are
    all accepted (`6.9-*`, `6.9.1-return-array/-function`,
    `-storage-register`, `6.9.2-linkage-conflict`).
