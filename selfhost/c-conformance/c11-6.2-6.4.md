# C11 6.2-6.4 (Concepts, Conversions, Lexical elements): stage08 cc

Range: N1570 clauses 6.2 (scopes, linkage, name spaces, storage duration,
types, representation, compatible types, alignment), 6.3 (conversions) and
6.4 (lexical elements), surveyed 2026-10-28 against the tree's
`selfhost/stage08/cc.s32x` with `probe.sh`.  99 probes
(`probes/6.2*.c`, `probes/6.3*.c`, `probes/6.4*.c`): **41 PASS, 9 DIAG,
11 WRONG, 23 REJECTS, 15 ACCEPTS**, no ORACLE, no HANG.  Several REJECTS
in this range are really keyword/operator gaps that belong to 6.5/6.7
(`_Alignof`, `_Alignas`, `_Generic`, `_Noreturn`, `_Thread_local`,
unary `&` on a function); they are listed here because the probes that
found them are here.

## Summary of gaps

WRONG code, most serious first:

1. **`double * <power-of-two int constant>` is miscompiled.**  `d * 2`
   gives `d`, `d * 4` gives `d / 2`, `8 * d` wrong too; `d * 3`,
   `d * k` (variable) and `d * 2.0` are right.  The emitted code is an
   `fdiv.d` against a constant, i.e. a strength reduction of
   integer-style multiply-by-2^k applied to a floating operand.  Hits
   long double the same way (`x * 2`).  `6.3.1.8-double-times-int`.
2. **`_Bool` is a typedef for `unsigned char`** (parser.h `add_typedef("_Bool", ...)`),
   so conversion to `_Bool` truncates instead of testing against zero:
   `_Bool b = 256` is 0, `= 0.5` is 0, `= &x` is the address's low byte,
   `(_Bool)2` is 2, `b += 1` on a true bool is 2.  `6.3.1.2-bool`.
3. **Unconditional `goto` into a braced block drops the whole function
   body.**  `goto L; { L: n += 5; }` compiles `main` to an empty body
   (then the link fails because the empty symbol is lost); with a
   conditional goto it works.  Smallest form is the probe itself.
   `6.2.1-label-scope` (shows as REJECTS: link error).
4. **`*f` / `**f` on a function designator** loads through the function
   address instead of yielding the function again; calling the result
   jumps into data (execute fault, exit 139).  `(*f)(x)` directly is fine.
   `6.3.2.1-func-designator`.
5. **Block-scope `extern int x;` binds to a visible local `x`** instead of
   the file-scope object (prints the local's value).  Without a shadowing
   local it works.  `6.2.2-block-extern-shadow`.
6. **Octal escapes beginning `\0` stop after the 0**: `'\001'` is 0,
   `"\0012"` is NUL,'0','1','2' (should be 0x01,'2').  `'\012'` is right.
   `6.4.4.4-octal-zero`, `6.4.5-escapes`.
7. **Unsigned bit-fields narrower than int do not promote to int**:
   `-f.u3 < 0` and `f.u3 - 8 < 0` are 0 (clang: 1).
   `6.3.1.1-bitfield-promote`.
8. **`sizeof` gets the type of arithmetic expressions wrong**:
   `sizeof(d + d)`, `sizeof(d + 0)`, `sizeof(f + 1.0)` are 4 (should be 8);
   `sizeof(+c)`, `sizeof(-s)`, `sizeof(~uc)` are 1/2/1 (unary operators
   not promoted for sizeof).  The values computed are right; only the
   static type is wrong.  `6.3.1.8-sizeof-arith`, `6.3.1.1-sizeof-promoted`.
9. **`\u` / `\U` escapes in string literals** are taken as the letter `u`
   plus digits (21 bytes instead of 11).  Raw UTF-8 source text in a
   literal is fine.  `6.4.3-ucn-string`.
10. Multi-character constant `'ab'` is 97 (first char) where clang gives
    24930.  Implementation-defined, but a divergence from the ABI-partner
    compiler.  `6.4.4.4-multichar`.

REJECTS of common C:

- `register` on a parameter (`int f(register int x)`).  `6.4.1-register-param`.
- `&function` anywhere (`not an lvalue (hir)` in a block; `expected
  constant integer` in a static initializer).  `6.3.2.1-func-address`.
- Pointer-to-array declarators `int (*pa)[10]`.  `6.3.2.1-array-address`.
- Brace-initializing a struct that has bit-field members.
  `6.3.1.1-bitfield-init`.
- `__func__`.  `6.4.2.2-func`.
- File-scope tentative `int arr[];` with no later size.
  `6.2.2-tentative-array`.
- Hex floating constants (`0x1p4`).  `6.4.4.2-hex-float`.
- Encoding prefixes: `L'x'`, `u'x'`, `U'x'`, `L"..."`, `u"..."`,
  `U"..."`, `u8"..."` (the prefix is lexed as an identifier).
  `6.4.4.4-wide-chars`, `6.4.5-wide-strings`, `6.4.5-u8-prefix`.
- `wchar_t` missing from `<stddef.h>` (clause 7).  `6.4.4.4-wchar-header`.
- Digraphs `<: :> <% %> %: %:%:`.  `6.4.6-digraphs`.
- UCNs in identifiers.  `6.4.3-ucn`.
- C11 keywords: `_Alignof`, `_Alignas`, `_Generic`, `_Noreturn`,
  `_Thread_local` all unrecognized.  `6.2.8-alignof`,
  `6.2.8-alignas-stronger`, `6.4.1-alignof-alignas`, `6.4.1-generic`,
  `6.4.4.1-const-type`, `6.4.1-noreturn`, `6.2.4-thread-local`.
  (`<stdalign.h>`, `<stdnoreturn.h>` and `<float.h>` are also absent from
  stage08/include.)
- `_Complex`: unsupported, and stage08 does not predefine
  `__STDC_NO_COMPLEX__` (it does define `__STDC_NO_ATOMICS__`), so
  portable code cannot detect the absence.  `6.3.1.6-complex`,
  `6.3.1.7-real-complex`.

ACCEPTS (missing diagnostics; stage08 does little type checking in this range):

- Incompatible redeclarations: `extern int q; extern long q;`,
  `int g(int); int g(double);`.  `6.2.7-incompatible-*`.
- Assigning between distinct struct types.  `6.2.7-struct-compat`.
- Assigning to a const object, or to an array.  `6.3.2.1-const-lvalue`,
  `6.3.2.1-array-assign`.
- Using a void expression's value (`int x = f();` with void `f`).
  `6.3.2.2-void-value`.
- Int-to-pointer and incompatible-pointer initializations without a cast.
  `6.3.2.3-int-to-ptr`, `6.3.2.3-incompatible-ptr`.
- `void v;` object.  `6.2.5-void-object`.
- Lexical: `09`, an integer constant too large for any type, `''`, the
  pp-number `0x1e+1` (taken as `0x1e + 1`), `_Imaginary` used as an
  identifier.
- `int v; static int v;` (undefined behaviour per 6.2.2p7, not a
  constraint; clang errors).  `6.2.2-linkage-conflict`.
