# The 1987 Desk

A plan for importing 80s/90s software culture into SLOW-32 without
breaking what the machine is.

Captured 2026-08-15, before it evaporated. This is a product and
culture roadmap, not an ISA change. The emulator is still the OS.
There is still no VGA, no AdLib, no boot sector, and no 8086 in a
box. The good trouble is software that *wanted* a character-mode,
file-oriented, application-level sandbox.

## The thesis

SLOW-32 is a desk from about 1987 that someone forgot to unplug.

The 80s and 90s did not win because of bitplanes. They won because a
spreadsheet, a database, a word processor, and a modem could all
share a directory of 8.3 files and a 24-line screen. We already have
two of those, a terminal service, and a filesystem. The rest is
getting into the right kind of trouble.

The filter for every idea below is the same:

- Does it want *this* machine (text, files, no MMU, no interrupts)?
- Is it native, the way dBase is native, not a vintage `.EXE` under
  an x86 emulator?
- Does it change the *job* of the box, or is it just another language?

If it needs a framebuffer, a mouse, or an operating system, it is a
different hobby.

## What is already on the desk

This is not a toy ISA with a hello world. It is already an unusually
complete period software museum, all guest-native:

| Surface | What we have | Period analogue |
|---|---|---|
| Words | `nano/` — full-screen editor, WordStar-handed keys, `term.h` | Pico/nano wearing WordStar's coat |
| Records | `dbase/` — dBase III, Teacher's Pet, `.DBF`/`.NDX`/`.FRM`/`.LBL`, BROWSE, `@SAY`/`@GET` | dBase III Plus, with Clipper leanings |
| Languages | C/C++ (LLVM + selfhost), Free Pascal, SLOW BASIC, Forth, Lisp, Prolog, Lua | The language closet of a well-funded lab |
| Query | `sqlite/` | The 2000s cousin; keep it as stress, not as the 80s story |
| Fiction | `zork/` — Z-machine, Mini-Zork | Infocom |
| Math | Native f32/f64, CORDIC, 64-bit integer story | The scientific half of the desk, unfinished |

SLOW BASIC already admits the constraint out loud: no `SOUND` /
`COLOR` / `DRAW` as hardware. It still has `PEEK`/`POKE`/`INKEY$`/
`LOCATE`, which is the honest home-computer texture. The terminal
service (`docs/SERVICE_NEGOTIATION.md`, `runtime/include/term.h`)
already exists because BROWSE, `@SAY`, and nano needed a real
screen. That service is the substrate for almost everything below.

Clipper is already leaking into dBase: trim-concat semantics, first
`PROCEDURE` as entry point, low-level file I/O. That is a hint, not
an accident.

## The hole in the middle of the desk

The 80s PC office was a trinity.

| Piece | 1983 name | Status |
|---|---|---|
| Words | WordStar | Partial — keys, not the document language |
| Records | dBase III | Product |
| Numbers | 1-2-3 / VisiCalc | **Missing** |

A spreadsheet is the missing killer app. Not "Excel, but sad." A
real character-mode calc: A1 notation, `@SUM`, `@IF`, circular-ref
detection, comma-as-next-cell, `/FS` to save. If it reads `.WKS` /
`.WK1` the way dBase reads `.DBF`, people will make a small unkind
noise.

Then make the three talk.

- `APPEND FROM BUDGET.WK1` into a `.DBF`
- Mail-merge a WordStar file from a dBase query
- Chart a range by writing HPGL, not by lighting pixels

That is Lotus Symphony / Framework / Enable: the actual 1986
fantasy. Almost nobody recreates it, because they start from a
framebuffer.

## What not to do

These are not "later." They are a different project.

- **Do not port Minix, Linux, or "a little DOS."** The first
  article's point is that the emulator *is* the OS. A boot sector
  ends that.
- **Do not emulate an 8086 so we can run real Lotus.** We
  reimplemented dBase instead of running `DBASE.EXE`. That choice
  *is* the project. A CP/M or DOS box is a fun weekend and a
  philosophical retreat.
- **Do not chase VGA, AdLib, SCUMM, or Sierra AGI.** The constraint
  is the aesthetic.
- **Do not start Lynx.** The honest pre-web internet is Gopher,
  finger, and files. The web is a different gravity well.
- **Do not add another language unless it changes the job.** We are
  already over-indexed. Smalltalk, Hypertalk, and Delphi all assume
  a mouse and a bitmap.

## Ranked trouble

Ordered by how much they belong on *this* machine, not by nostalgia
density.

### 1. A 1-2-3-shaped spreadsheet that can see a `.DBF`

Completes the desk. Formula engine is a compiler-adjacent problem
and will be enjoyable for the same reasons dBase's expression
evaluator was.

Minimum viable:

- Grid, cursor, status line, `term.h`
- Numbers, labels, formulas, A1 / relative / absolute refs
- Recalc with cycle detection
- `.WKS` or `.WK1` load/save (even a documented subset)
- Import/export a dBase work area, or `COPY TO ... TYPE WK1` on the
  dBase side

Out of scope for v1: a full macro language, 3D workbooks, graphs on
a canvas. Charts go to a plotter file (see "Graphics without a
framebuffer").

Suggested home: `sheet/` (or `calc/`), parallel to `dbase/` and
`nano/`.

### 2. COMMAND.COM, or something that answers to `DIR`

Right now the museum is a pile of `.s32x` files. One shell with
`DIR`, `COPY`, `TYPE`, `REN`, `PATH`, and `.BAT` changes the
feeling from "toolchain" to "a computer."

`AUTOEXEC.BAT` that launches a numbered menu (Automenu / Direct
Access) is cheap theater with outsized payoff. Do not build DOS.
Build the *habit* of DOS.

Minimum viable:

- Interactive prompt and a batch runner
- Internal commands that match muscle memory
- Launch a `.s32x` via the host `exec` service (already sketched in
  service negotiation) or a well-defined convention
- A one-page startup menu: nano, dbase, sheet, sbasic, zork

Suggested home: `command/` or `dosish/`. Name it when it exists.
The prompt can say whatever it wants as long as `DIR` works.

### 3. Either Clipper or a dBase-backed BBS

Two options, one desk. Both are native. Both use the thing we
already built better than anyone.

**Clipper** is the compiler story. `s32-clip payroll.prg` → a
native `.s32x`. We have LLVM and a self-hosting C compiler.
Nantucket's joke was "dBase, but it compiles." That is the most
on-brand compiler story left in the tree.

**A BBS whose user file is a `.DBF`** is the social story.
WWIV / PCBoard / RBBS were databases with a modem bolted on.
Message bases, doors, user records, last-call dates — that is all
dBase. The "modem" is a host socket behind the `net` service
already sketched in `docs/SERVICE_NEGOTIATION.md`. A QWK packet
tosser is 1993 offline mail, which is the most 90s thing that is
still just files.

Pick one first. Clipper if the week wants a compiler. BBS if the
week wants a modem light.

### 4. Rogue, then maybe Hack

We already paid for this. `term.h` exists. Rogue is why curses was
invented: 80×24, `@` and `.` and `D`, save file, permadeath.

nethack is the "does your C compiler actually work" boss fight.
Rogue is the Saturday afternoon. Do Rogue first.

### 5. Kermit (after there is a second endpoint)

Kermit is a file protocol for a hose. It is not the comms program
the machine is missing the way 1-2-3 is the office program it is
missing. The missing thing is **a second endpoint**. See
[hose.md](hose.md).

v1 of that hose is IPv4 TCP, numeric addresses only (`net/`).
Kermit waits until two guests (or a guest and a denied-`fs` jail,
or a human with SyncTERM) share a pipe and not a disk.

### 6. Inform 6 on top of the Z-machine we already have

We can play Mini-Zork. The 80s/90s move is to *write* new
Infocom-likes on the same box. Inform 6 is small, mean C. Author on
SLOW-32, compile to `.z5`, play in `zork/`. That is a closed
creative loop, which the language museum does not give you.

### 7. The 90s internet that is not the web

All text. All tiny.

- Gopher (1991): one protocol, menus that are files, phlogs
- finger and whois
- tin or slrn, if an NNTP bridge ever exists
- ircII, if `net` ever happens

Gopher in particular is the anti-web, and it will look like it was
designed for this ISA.

Needs the `net` service. Until then, a Gopher client that reads a
local file tree is a legitimate offline mode and a good first slice.

### 8. Languages, only if they change the job

- **Fortran 77 + a LINPACK kernel.** We already have CORDIC and
  native f64. 80s science was Fortran talking to a plotter, not
  Python talking to a GPU.
- **COBOL**, but only if payroll hits the dBase files. GnuCOBOL is a
  compiler story; a COBOL that `WRITE`s `.DBF` is a business story.
- **A real WordStar**, not just the keystrokes. Dot commands
  (`.pl`, `.cp`, `.pa`), columns, mail merge. nano is Pico's
  grandchild wearing WordStar's coat. WS4 was a document *language*.
- **Finish Prolog.** Nested `findall` / `\+` is the bug that keeps
  the 80s AI-lab set from being the real thing. See
  `docs/AUDIT-2026-08.md` §7.6.

### 9. The Borland desk

We have the FPC backend and we have sbasic. We do not have the
**blue screen**.

A character-mode IDE — edit, compile, run, WordStar diamond,
one-key compile — around sbasic or Pascal is Turbo Pascal 3/5 as a
feeling. Turbo Vision is the toolkit (windows, menus, status line
on a text grid). Sidekick as a popup calculator / notepad /
calendar is the TSR fantasy, and it can live as a cooperative
switcher on the *host* without adding interrupts to the ISA.

Guest-side `DEBUG.COM` (dump, unassemble, go, break) sits next to
`slow32 -s` and is the most 80s program that is actually about
*this* instruction set.

## Graphics without a framebuffer

sbasic already told the truth. The period-correct escape hatch is a
**plotter**.

- HPGL or Tektronix 4014 to a file; the host renders SVG
- Logo's turtle, a spreadsheet chart, a dBase form — 1982 lab
  culture, no framebuffer
- Sixel / ReGIS if it should draw *in* the terminal we already have
- ANSI + SAUCE + a TheDraw-style editor: the 90s underground
  version of the same idea. Makes a BBS look like a BBS

A plotter service can start as "write a file." It does not need new
MMIO on day one.

## Suggested fight order

If picking a fight this month, in this order:

1. **Spreadsheet that can see a `.DBF`.** Completes the trinity.
2. **`COMMAND.COM` + a one-page `AUTOEXEC` menu.** Turns the repo
   into a machine you sit down at.
3. **Clipper *or* a dBase-backed BBS.** Compiler week or modem week.

After that, Rogue and Kermit are dessert.

Do not start all three. The whole point of a 1987 desk is that the
same files keep showing up in different programs. Each new program
should open something the last one wrote.

## Substrate the plan depends on

None of this asks for a new ISA. It asks the host to keep being a
good 80s peripheral cabinet.

| Need | Where it already lives | Notes |
|---|---|---|
| Full-screen terminal | `term.h`, service negotiation `term` | Unlocks sheet, Rogue, IDE, TheDraw, WordStar |
| Files | MMIO fs / libc | Unlocks everything; 8.3 is a convention, not a limit |
| `exec` | Planned in `SERVICE_NEGOTIATION.md` | Unlocks COMMAND.COM launching apps |
| `net` | v1 landed: IPv4 TCP, no DNS (`net/`, opcode `0x40–0x48`) | Unlocks two-guest pipes. DNS, UDP, Unix sockets, `poll` later |
| Plotter | Nowhere yet | Can be "write `out.hpgl`" until it deserves a service |

Graceful degradation stays the rule: no `term` means LIST instead of
BROWSE, line-mode calc instead of a grid, INKEY$ that never fires.
No `net` means a BBS you walk up to at the console, and a Gopher
that reads a directory.

## Working names (do not treat as decisions)

- `net/` — **landed** IPv4 TCP hose (numeric only)
- `command/` — **v1 landed** DIR/TYPE/COPY/REN/DEL/CD (no .BAT, no exec)
- `sheet/` — **v1 landed** formula engine, term grid, WK1 + DBF interchange
- `bbs/` — **v0.2 landed** DBF logon + DBF message base (list/read/post)
- `clip/` — dBase-to-native compiler
- `bbs/` — dBase-backed board
- `rogue/` — the Saturday afternoon
- `kermit/` — the comms program (needs the hose first)
- `inform/` — authoring for `zork/`
- `gopher/` — the anti-web
- `ws/` — WordStar the language, if nano is no longer enough

Names are cheap. The files they share are not.

## How to add something to this plan

Write it down here *before* it becomes a directory. The test is
still the thesis at the top. If the idea needs a boot sector or a
framebuffer, it goes in a different document, or in the bin.
